## P0/P1 BLOCKERS

无。以下前轮成立的问题已通过当前源码复审关闭：

- 构建基线及原生审查调用路径已对齐，兼容适配不再停留于不可达入口。
- 同机备份文件检查改为有效 Docker 执行方式，TAR 与 ZIP 格式不再混用。
- 恢复不吞掉复制和 SQL 错误，保留文件、数据库回退点，诊断 I/O 失败不阻断回退。
- 恢复辅助容器可连接目标数据库；按实际共享数据卷原子加锁，锁贯穿验证、提交与回退。
- 恢复失败还原原数据库后重建 SSH 公钥授权，避免残留源实例的 key ID 映射。
- SECRET_KEY 使用数据卷文件 URI，备份恢复迁移源密钥，重跑安装不覆盖恢复后的密钥；不支持的配置在修改前拒绝。
- Docker SSH 固定池键避免按 API URL 累积连接池，所有远端通道仍使用已固定指纹和专用私钥。
- 验证结果与任务最终成功分离，仅在事务完成之后发布最终状态。
- 正式执行器启动失败验证兼容版，双失败按 AI 不可用处理；长任务健康刷新已移至独立线程，不再依赖审查结束。

用户明确暂不提供真实模型，因此真实模型审查效果未验收，协议样本通过不能替代模型业务质量。断电后未完成恢复的处理边界仍应在交付说明中列出。诊断包独立判因见 `oneclick-v2-diagnostic-blind-review.md`，不把受控错误注入等同于真实硬件故障。
