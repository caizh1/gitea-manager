# 新包自动卸载旧实例修复

## 根因与修复

用户确认在新解压的 `/tmp/.../manager` 目录运行卸载，而原实例由旧包安装。旧代码在新目录缺少 `state/installation.json` 时跳过全部容器删除，却输出“卸载完成”。已通过修复前回归测试复现返回码为 0、删除范围为空的错误。

修复后从 Docker Compose 项目标签自动发现同产品实例及其原工作目录，交叉核对原安装身份。唯一候选自动选中；多个候选显示实例和端口，输入序号选择。当前目录若自身对应仍存在的实例，优先卸载当前实例。用户无需查找或输入旧包路径。不能验证归属或没有资源时返回失败，不能将未执行删除报告为成功。

自动定位后获取原目录的生命周期锁、安装锁，再核对身份；两次确认后按选中项目标签精确删除资源，并删除原目录状态。原有 Manager 数据库业务记录防护继续保留。新包目录和其他实例不删除，诊断仍写入运行脚本的新包目录。

## 验收

- 卸载 11 项单测与安装 11 项回归通过，共 22 项；Shell 语法与 Python 编译通过。
- 真实 Docker Go 模板验证通过。审查中发现的方法括号问题已在交付前修复。
- Ubuntu 24.04 amd64 中启动完整 Manager 的 7 个服务，包括 frontend、backend、approval-view、review-executor 和 3 个后台进程。
- 在不含原安装记录的新包目录执行卸载，自动发现旧实例；多实例选择后取消确认，7 个服务继续运行。
- 确认卸载后核对目标容器、卷、网络均不存在，原状态清除，同一端口可重新绑定。
- 同目录同端口重建完整 Manager 后，7 个服务运行且 HTTP 会话接口可访问，再次自动卸载清理测试实例。
- 独立 P0/P1 复审结论 PASS，无成立阻塞项。审查发现的 macOS 测试临时目录路径规范化问题已修正并重跑通过。

上述为独立测试机验收，不代表已远程操作用户现场机器。原安装目录或身份记录已经丢失的实例不自动猜测删除。完整交付仍保留 AI 冷重启未通过、真实模型未验证的边界。
