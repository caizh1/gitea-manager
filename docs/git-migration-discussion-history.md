# 讨论历史状态与行为差异确认

第七版接收协议保存 GitLab 普通讨论和行内讨论的只读来源快照，包括线程身份、父议题或请求、评论顺序、可解决状态、解决状态，以及来源提供的解决人和解决时间。未提供字段不补造，普通讨论不转换成代码评论。评论正文、附件、作者和时间继续保存在原生对象中。

线程详情按来源顺序展示各评论的状态、解决人及解决时间，字段缺失显示“来源未提供”，显式空值显示“来源返回空值”。目标评论删除后保留历史并提示“目标评论已删除”。父议题或 PR 删除后，数据库快照保留，列表隐藏相应记录，详情返回 404；管理员没有额外读取例外。原始 JSON 收入折叠区域。

目标评论旁的“迁移时”状态表示固定来源快照，不表示 Gitea 当前审批结论。线程入口保留原始字段，遵守所属议题或请求的读取权限。目标合并、编辑评论不会改写来源历史。

## 管理员操作

当来源启用“全部讨论必须解决”时，预检列出受影响项目、线程数和待解决线程数。管理员核对并一次确认本批次采用 Gitea 原生合并行为后，系统重新执行完整检查。未经确认不能正式启动。

确认绑定固定盘点、目标身份、目标群组和差异清单摘要，并记录原发起管理员和时间。修改输入、伪造摘要或使用其他账号不能沿用确认。数据完整性校验仍然独立执行，确认行为差异不代表允许丢失讨论状态。

新迁移保留来源的讨论限制设置用于审计，但不启用迁移额外讨论门禁。其他 CI、审批及分支保护继续按原有转换和验证执行。

## 接口与兼容

- 接收能力：协议七，要求 `discussion_snapshots=true`。
- 新对象：`discussion_snapshot`，同一接收会话按来源线程编号幂等保存到迁移历史，与评论回执关联。字段或关联不一致时，回读、封存和发布核验失败。
- 预检详情：返回 `compatibility`，包含 `differences`、`digest`、`acknowledged` 和确认记录。
- 确认入口：`POST /api/git-migrations/preflights/{id}/compatibility-acknowledgements`，请求携带 `digest`；只能由原发起管理员确认，成功后重新排队检查。
- 旧的未开放预检需保留现场并重新盘点、预检；旧协议结果不能直接发布。已开放旧任务标记“讨论历史状态未核验”，不自动补录或修改原规则。
- 旧协议已发布但成功回执尚未保存时，“继续任务”先核对接收端批次、管理员及每个仓库会话身份，只恢复 Manager 成功回执并释放互斥，不要求旧协议从未保存的新确认记录。协议七仍核对原确认；未知状态、身份不符或缺少回执不自动解锁。

## 验收范围

固定基准覆盖字段缺失与真假值、普通及行内线程、多条回复、幂等写入、篡改拒绝、差异确认、真实合并后历史状态、后台页面和权限。真实大型企业批次、其他版本和物理生产宿主机继续保持未验证。本修复不声明跨平台功能完全一致或故障概率为零。
