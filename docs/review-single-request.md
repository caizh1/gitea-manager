# 默认单次 PR 审查

新任务默认一次审查完整 PR，当前支持上限为净增加 1000 行，按固定 PR diff 的新增行数减去删除行数计算，跨文件累计；净减少按 0 行净增加计。所有新增和删除仍完整审查。例如新增 1500 行、删除 500 行，净增加为 1000 行，但实际审查覆盖 2000 行。上下文行不计入净增加行数，但计入模型输入额度。

主审会同时看到全部变更与已解析关系所需的固定版本上下文。P0/P1 候选汇总后一次独立反证，逐项返回结论。历史意见的生命周期核对仍按既有规则运行，不能把“一次主审”理解为任何任务永远只发一个模型请求。

默认输入目标 65,536 Token，输出额度 32,768 Token；实际输入还受模型窗口及安全余量限制。净增加 1000 行以内不保证一定装得下：完整源码和保护上下文超过额度时明确停止。净增加超过 1000 行时在调用模型前拒绝，不截断代码、不自动分批；反证超额或输出截断也不自动拆分。

JSON、位置、证据范围、候选完整覆盖和完成状态仍严格校验。明确的位置错误可纠正一次，不能删掉意见、改写正文或降低级别来通过校验。

分批实现保留，配置字段 `batch_splitting_enabled` 默认 false，当前页面不增加启用入口。以后明确需要时可通过管理配置显式启用。新任务使用流程版本 5，已存在的任务保留原流程与计划；切换模式只影响新任务，不静默重写运行中的任务。

## 验证

回归覆盖 1000 行单次装入、1001 行拒绝、新增删除跨文件累计、净增加准入与完整变更覆盖分别计算、Token 超额拒绝、未改动保护上下文保留、反证完整候选、禁止输出截断后自动拆分以及旧任务冻结。新增规则和执行路径定向回归 93 项通过，前端构建与 5 项诊断测试通过，后台页面显示单次模式与净增加限制且无浏览器异常。完整 AI Review 回归 644 项通过（含保留分批路径的压力测试），最终净增规则与执行路径定向回归 93 项通过。

新默认流程在独立 Gitea／Manager 中对净增 1000 行的固定嵌入式样本完成真实模型验收：1 次主审、1 次独立反证、0 次关联复核、0 次引用纠正，总计 171 秒。实际输入与计划一致，1000 行覆盖无遗漏、无重复；两个报告均通过结构、位置和候选校验。Gitea 回读 1 条 Review、12 条行内评论，提交与位置匹配。

当前净增 1001 行的真实 PR 返回 `PR_CHANGE_LIMIT`，模型调用为 0。跨文件新增 1500 行、删除 500 行的回归则通过净增检查，审查计划保留全部 2000 行。没有减少检查范围来符合行数门槛。
