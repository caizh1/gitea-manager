## 修复范围与验收条件

本次处理三项确定性问题，目标用户为 Manager 管理员。人工基线是：空仓库接入失败后需要先补提交才能退出；重复备份记录需要人工辨别；过期审查任务需要进入详情才能确认不再排队。

1. 空仓库接入失败后，管理员可直接移除本次接入。验收要求为：不创建首个提交、不删除仓库、只清理能够证明属于本次创建的通知、保留其他通知及审查历史。
2. 同一服务器已有等待执行、执行中或等待恢复的备份时，新的手动备份请求返回冲突。验收要求为：首次请求正常创建，快速重复、八线程并发和两个独立进程请求最终均只保留一条备份；其他服务器以及已结束且完成恢复的任务仍可正常创建。
3. 过期审查任务的列表与详情统一显示“版本已过期”。验收要求为：包括尚未开始的任务和已有原生会话的任务；保留数据库原始阶段，不影响正在执行的任务。

上述标准验证操作闭环和数据不变量，不等同于真实用户人工精力减少百分比；没有进行内网用户耗时测量，不宣称达到人工节省 80%。

## 实现与保护边界

- 移除与安装共用现有跨进程通知锁。仍先检查配置版本、归属、运行任务和不确定发布，再停止新审查并清理通知。
- 已创建但尚未完成投递验证的通知，使用持久创建编号，或创建响应丢失时使用持久随机名称查找；再核对通知类型、回调、仓库和密钥指纹。找回的编号在删除前保存，删除响应丢失或进程中断后继续核对同一编号，不重新创建通知。
- 创建结果仍不可确认、回执不唯一、通知被替换或指纹不匹配时，继续保留待核对状态，不猜测删除。安装尝试前已有的通知不因本次失败接入移除而被删除。
