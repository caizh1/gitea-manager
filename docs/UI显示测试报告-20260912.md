# Gitea Manager UI 显示测试报告

日期：2026-09-12。结论：本轮确认的显示缺陷已修复；52 个页面与尺寸组合的布局检查通过。

## 范围与证据边界

目标用户是日常管理 Gitea 的管理员。人工基线是逐页检查文字、按钮、滚动、弹层及窄屏布局。本轮覆盖现有页面的显示和只读交互，不修改真实仓库、备份、恢复、策略或审查任务。

- 浏览器：macOS 上的 Codex 内置浏览器；视口为 390×844、768×1024、1280×720、1440×900。
- 布局矩阵：仪表盘、服务器、备份、恢复、定时任务、镜像、提交门禁、仓库策略、AI 审查、统计、作者列表、作者详情、设置，共 13 页 × 4 种尺寸。
- 补充场景：登录、服务器详情、空数据、接口失败、长错误、120 条列表、筛选、分页、展开日志、长表单、抽屉及告警弹层。
- 固定样本通过真正的生产构建页面展示，通常每类 120 条；作者列表遵循现有接口的 100 条上限，策略和 AI 任务遵循分页。样本服务仅绑定回环地址，拒绝全部业务写请求。
- 另用本次构建的 Linux/amd64 前端镜像连接本地真实测试后端，完成登录、真实 AI 任务列表和响应式显示检查。固定样本不是 120 台真实服务器验收。

## 已修复问题

| 问题与原因 | 修改后的表现 | 复核结果 |
|---|---|---|
| 全局主按钮渐变覆盖文字、链接和朴素按钮，造成蓝字蓝底 | 渐变仅作用于正常实心按钮；文字按钮保持透明底色，禁用态沿用组件状态 | 真实列表的“详情”文字为 `rgb(23,101,190)`，背景图为 `none` |
| 语义色、辅助文字和时间过浅 | 加深主色、成功、警告、危险及辅助文字；移除已解决告警的整体透明度 | 四种正常实心按钮与白字的基础色对比度分别为 5.77、5.73、5.84、5.48；这不是整站无障碍认证 |
| 表格随数据无限增长 | 全部 20 处表格增加视口相关最大高度，数据在表体内滚动；明细表使用独立上限 | 52 个布局组合均无表格超过 600px；笔记本主表为 420px，手机主表为 544px |
| 固定操作列透明，横向滚动时下层文字透出 | 表头、固定列、条纹行和悬停状态使用明确底色 | 桌面列背景清晰；手机取消过宽固定列并保留横向滚动 |
| 窄屏侧栏占用过多宽度，菜单底部不可达 | 小尺寸自动折叠侧栏；菜单区域独立滚动；折叠按钮可用键盘操作 | 四种尺寸均无页面横向溢出和关键容器越界 |
| 长弹窗超屏，关闭或底部操作被挤出 | 限制弹窗宽高，标题、关闭按钮、正文、底部操作使用正常布局；正文独立滚动 | 手机长表单宽 366px，取消和保存仍可见 |
| 工具栏和表单在窄宽度互相挤压 | 工具栏自动换行；手机表单纵排；按钮与图标保持正常文档流 | 服务器、策略、门禁、恢复与设置页复核通过 |
| 仪表盘和镜像卡片随数量无限增长，统计数字断行 | 列表区域限高；卡片不被压缩；数字保持同一行；统计卡响应式排列 | 120 条样本显示正常，`80/120` 不再拆行 |
| 告警数量压住铃铛，长服务器名挤压状态 | 铃铛与数量使用并排布局，告警标题自动换行，内容区限高 | 手机告警弹层未越界，文字和时间清晰 |
| 图表不随容器宽度重新绘制，窄屏标签拥挤 | 监听容器宽度并按像素比重绘，限制柱宽并按可用宽度抽稀标签 | 手机统计图显示宽度与容器一致，缩放后重绘正常 |
| 自动刷新可能丢失已展开日志 | 定时任务表绑定稳定的行标识，日志表独立限高 | 展开后跨自动刷新仍保持，明细表最大 360px |
| 分页、空态混用英文，图标控件缺少名称 | 启用中文组件语言，补充导航、告警、编辑和删除的可访问名称 | 主要页面未发现可见的无名称按钮，空态与分页中文显示 |

## 构建与一致性

- `npm run build` 通过；`git diff --check` 通过；固定样本脚本语法检查通过。
- 前端、后端、执行器的 Linux/amd64 镜像构建通过，标签为 `ui-20260912`。
- 32 个前端构建文件与运行镜像及实际 HTTP 响应逐文件一致；67 个后端 Python／依赖清单文件、执行器源码与各自镜像一致。这里只确认交付内容一致，不扩大为本轮后端业务验收。
- 使用现有固定打包器更新 `gitea-manager.tar.gz`，文件与镜像清单、部署方法随包交付；包的最终摘要见同目录 `.sha256` 文件。
- 保留工作区原有的策略中心、AI 审查等其他改动；本轮没有提交代码或替换生产服务。
