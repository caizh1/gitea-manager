# 接口失败提示修复与验收

日期：2026-10-15。

## 根因

重新审查请求先由后端读取真实 PR 状态。`backend/ai_review/gitea.py` 的 `version_of()` 遇到已关闭或已合并的 PR 会抛出“PR 已关闭或合并”，路由返回带 `error` 的 HTTP 400。该拒绝符合现有规则。

前端 `AIReviews.vue` 将操作失败写入页面顶部的 `error`，没有弹出提示。任务列表每五秒读取成功又会清空同一个字段；详情页滚动后顶部提示还可能位于可视范围之外。公共 Axios 响应拦截器此前只广播会话和权限事件，没有提供错误提示兜底。

## 修复

- 公共请求层统一广播可见错误，使用已有 Element Plus 显示八秒、可关闭的通知；同一错误对象只通知一次，相同消息合并展示。全屏详情时通知挂在当前全屏元素内。
- 保留请求拒绝语义与原有表单错误区域；请求失败不会进入调用方的成功分支。超时、断网、HTTP 网关错误均有可读提示。
- 下载接口失败时解析不超过一 MiB 的 JSON 错误 Blob，成功二进制响应保持原样；非 JSON 或超限错误使用 HTTP 状态提示。
- AI Review 操作错误与任务列表读取错误分开。成功轮询只清除列表连接错误；下一次写操作或用户关闭提示才清除上次操作错误。详情中也保留操作原因。
- 后台轮询显式设置 `notifyError: false`，延用区域连接提示，避免反复弹窗。取消请求、旧组织范围响应、登录探测及会话过期延用原有处理，不生成公共错误通知。下载错误异步解码后再次校验权限代次。
- 策略、审批、备份、恢复、提交门禁等已有弹窗改用共享通知入口，避免与公共请求层重复通知。
- 问题台账读取失败时显示所属区域；此前台账没有历史数据时，区域条件会同时隐藏错误。
