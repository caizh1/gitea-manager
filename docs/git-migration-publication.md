# 预迁移通过后的正式开放边界

## 目标与前提

面向迁移管理员，在来源及依赖已停写、网络与存储可用的前提下，避免正式阶段重新执行已经通过的导入操作。人工基线是对预演数据重新逐仓交接、发布制品、安装规则并核验；系统应复用已完成的固定批次，只读复查后整批开放。本次属于正确性修复，不以固定样本推导人工节省百分之八十或任意来源的成功概率。

## 有效期

三十分钟有效期限制管理员提交正式启动请求的时间。过期结果不能提交新请求；在有效期内已被接受的请求，允许完成耗时较长的复检，不因执行跨过截止时间而自行失败。来源、人员映射、目标身份和权限仍需复核。已中断且结果过期的预迁移继续执行时，重新进行预演并要求新的停写确认。

## 正式阶段

第五版批次必须携带完整的预演通过记录、全部仓库稳定编号和同一批次标识。正式任务重新核对来源元数据、独立清单、Git/Wiki 引用、目标身份、容量与权限，然后仅调用一次整批发布接口。

正式阶段不再次调用仓库交接、创建制品、附件导入、规则安装或代码传输。目标接收端在同一事务中重新验证预演指纹、仓库配置与历史对象，再开放整批仓库。所有依赖的实际写入操作均已在预迁移阶段执行并验证。

发布成功后若管理端没有收到回执，继续执行仅查询原批次状态和稳定仓库编号，不再次发布。已经开放的历史批次仍按原有协议和检查点恢复；新逻辑不重写历史来源数据。

## 检查和验收

- 固定时钟回归：有效期内提交、复检跨过截止时间仍可完成；过期后首次提交仍被拒绝，来源变化仍被拒绝。
- 状态机回归：缺失预演标记、对象核验未完成、批次或仓库身份不符时禁止开放。
- 实际隔离批次：预迁移结束后禁止任何准备性写入，正式阶段只允许整批发布；核对开放前后仓库编号、引用、文件、历史对象和保护规则。
- 故障恢复：发布回执丢失后不重复发布，取消和重新预迁移仍保持归档副本与原路径语义。
- 完整回归：使用 GitLab CE 与 Gitea 的既有固定矩阵及最终包镜像，验证消费端下载、合并与规则行为。

支持范围仍以当前迁移文档为准。GitLab EE 付费能力、其他版本、生产物理宿主机和真实大型企业容量未经实测时保持未验证；OCI 按既定范围排除。

## 字段完整性修复

第五版协议补齐议题与合并请求的截止日期及讨论锁定状态。独立来源清单增加逐对象字段核验，接收端写入原生字段并在封存与发布前回读，不能只按对象数量判断完整。第四版预迁移结果不能直接用于第五版正式开放，需重新盘点和预迁移。

发布接口只返回状态，管理端随后查询持久化批次核对标识、管理员和仓库数量；不把精简发布响应误判为缺少身份。真实接口与回归桩使用相同响应结构。
