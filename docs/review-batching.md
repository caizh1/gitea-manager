# 大 PR 分批审查：内网验证说明

本次实现面向已有 Gitea Manager 的 AI 审查用户。输入限定为固定版本的 PR 标题、描述和完整 diff；没有源码工程读取或命令执行工具。目标是降低人工阅读、判断和重复操作的成本，人工精力降低 80% 为待验证目标，不是已完成指标。

## 使用方式

1. 在 AI 审查设置中填写服务实际开放的上下文窗口，不使用模型宣传页的最大窗口代替。
2. Token 计数可自动匹配 Qwen3.8-27B、DeepSeek-V4.1-Flash 及其官方组织前缀。内部别名需要手动绑定；其他名称使用明确标注的保守估算。
3. 新安装默认单批输入目标为 65536 Token，模型输出额度为 32768 Token；另扣除至少 2048 Token 或窗口 5% 的安全余量。升级保留已有配置和历史任务预算；旧配置缺少这两个字段时仍沿用输入 32768、输出设置 0（分批执行时使用 8192）的兼容行为。显式设置输出为 0 也继续使用 8192。
4. 含反证的调用上限超过 8 次时，在详情页确认具体计划。确认前不发送审查模型请求。PR 更新使旧计划失效。
5. 默认累计执行预算 3600 秒。暂停后可以追加预算；已完成单元不会重跑。未知结果继续核对原会话，只有明确失败的单元可以主动重试，重试计入新的成本门槛。
6. 所有必要单元完成后统一发布。中途失败保留 Manager 中的结果，PR 仅更新状态与覆盖信息。

设置中的“核对 Token 计数”会发起最多四次短样本请求，对比本地编码和服务返回的输入用量。本地编码计数不等于服务计费结果；服务端聊天模板、思考模式和额外提示均可能产生偏差。

## 离线资源

两份 tokenizer 资源随部署包交付，只使用 CPU，无需模型权重、PyTorch 或 GPU。运行期间不联网下载。

- Qwen3.8-27B：固定提交 `1d4bf0f2ff6012fd82039f2fa52739d0dd7c60c0`。
- DeepSeek-V4.1-Flash：固定提交 `314113f8a7dadb388215396ba5fbee2c610a04d6`，编码库 `deepseek-recipe==0.2.0`。
- 来源、许可证、原始文件摘要与编码器版本见 `backend/ai_review/assets/tokenizers/manifest.json`，新增离线依赖摘要见同目录 `wheels.json`。

任务保存资源契约。升级时必须保留尚未结束任务引用的资源目录；缺失或摘要不符会明确失败，不会悄悄换用另一套 tokenizer。

## 执行和恢复边界

优先按文件分组，再按修改块和原始行区间切片；重叠上下文不重复计算覆盖。全局定位不随分批重新编号。关联索引只是依据 diff 查找可见线索，不代表完整调用图或 diff 外依赖验证。

计数在独立进程中串行运行，默认超时 120 秒、Linux 常驻内存预算 512 MiB。完整请求在 Broker 发送前再次校验；计数缓存按输入、参数和资源摘要隔离，不保存 PR 正文。

原始 diff 获取边界仍为 64 MiB。这是抓取上限，不是所有 64 MiB 输入都能完成审查的保证。超长单行、无法安全解析的文本、关联规模超界或计数资源不足会明确进入未完成状态，不静默丢弃后声称完成。

单元结果先落库再 ACK。每个批次拥有独立会话、事件序号和尝试记录；同一父任务串行执行，每批释放调度位置。取消对整个父任务生效。执行器回执未知不得通过重新调用模型“恢复”。发布回执未知使用原有只读核对流程。

分批报告和候选反证结果允许一个完整的 `<think>…</think>` 前缀，以及包住完整 JSON 的外围 Markdown 代码围栏。原始响应保留，思考内容不作为审查结论；移除外围包装后仍须完整解析唯一 JSON 对象并通过全部字段、证据引用和候选核对。未闭合标签、截断输出、任意开场说明、其他 HTML 包装或 JSON 后的附加内容不会被自动截取或补齐。

证据引用以本单元 `F…H…L…` 编号为规范形式。模型将同一单元的 `R…` 定位编号放入证据列表时，仅在该编号唯一对应一条本单元证据的情况下转换为规范编号；主审与反证共用此规则。不存在、跨单元或有歧义的引用仍然拒绝，定位必须属于该意见引用的证据。不会按相邻行、相似文字或全局编号猜测。此转换不修改原始响应或已冻结的分批输入。

新增数据库结构为增量迁移，旧单会话任务保留旧协议。运行数据、数据库、密钥、工作目录不应进入离线包。

## 内网验收清单

用户已选择在内网执行实际模型验收。两款模型分别测试，不能互相替代：

- 用当前失败 PR、至少 20 个真实 PR 和 20 个定向正反样本，冻结输入版本并建立人工缺陷基准。
- 验证服务计数偏差、思考开关、中文、代码与 `<think>` 等字面特殊标记。
- 验证 8/9 次调用门槛、确认后 Push、超时、取消、维护、重启、未知回执和预算续跑。
- 在目标宿主机测量 1/10/64 MiB 输入的首次加载、热计数、完整计划时间与峰值内存；记录 CPU、架构和容器限制。
- 统计 P0/P1 精确率及召回率，目标各不低于 90%；单独检查分批边界严重缺陷。
- 记录完整人工阅读、误报核对、补查、重试和整理耗时，对照人工基线；未经测量不能声称节省 80%。

## 当前验证限制

本机为 macOS ARM，Linux amd64 镜像通过架构模拟运行。512 MiB 预算下，两款模型 1 MiB 短基准完成；10/64 MiB 全文编码触发内存保护。因此原计划的 10 MiB 热计数 P95 ≤ 5 秒、64 MiB ≤ 30 秒尚未达到，不以公开基准替代实测。

当前历史复核会收集原问题同路径的 diff；同路径修改极大或本轮候选过多时仍可能超出额度并停止发布。预计耗时尚未建立足够的实际服务样本，页面显示“样本不足”。完整的故障注入矩阵、浏览器窄屏验收、实际模型效果和目标宿主机性能须继续验证。

本次交付定位为内网验证候选版本，不能据此宣称整套生产验收或人工节省指标已经完成。
