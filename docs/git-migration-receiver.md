# Manager 高级迁移接收端

本实现基于当前增强版的独立源码快照，继续用于开发和隔离验收，不构成生产升级批准。迁移协议提升为第二版，必须与配套 Manager 使用；业务账号和授权由管理员提前配置。

## 原生接收语义

- 同一批次先建立所有私有隔离仓库及代码，再导入跨仓库合并请求。请求的来源仓库使用稳定编号，必须属于相同管理员、相同批次且仍在装载中的隔离会话。不能借来源编号关联外部或已交接会话。
- GitLab 分支模式使用大小写敏感的星号匹配，并合并全部相交的迁入规则。推送、合并和强推采用来源语义；原有非迁入规则继续遵守原生优先级。主体使用已确认的静态账号映射，不自动同步来源成员变化。
- GitLab 受保护标签分别保存创建者和删除维护者。Git 更新与删除受保护标签一律拒绝；维护者可使用原生界面或接口删除。普通 Gitea 标签规则保持其原生语义。
- 通用、npm、Maven、PyPI、NuGet 和 Helm 制品在封存交接时发布为原生制品。正文和来源文件摘要逐项核对，不覆盖外来同名包。npm 以源注册表版本元数据为准保留依赖、说明、分发标签和扩展安装字段；NuGet 的生成清单与源端提供的清单必须逐字节一致才能复用。
- CI 历史、日志、原始报告及构建文件使用私有仓库的迁移历史入口保存。历史批准不计入当前批准，迁入工作流不自动执行，Actions 默认关闭。

## 数据迁移

第三百八十三号迁移扩展批次标识，第三百八十四号迁移扩展 GitLab 分支语义，第三百八十五号迁移扩展 GitLab 标签语义。升级必须保留原数据库与回退材料，不能把此源码直接套用到未验证版本。

## 真实验收

完整链路由 Manager 仓库中的高级来源、CI、迁移、协议和规则验收脚本执行。验收需要真实来源服务、配套接收端和独立 Worker；仅单元测试或接口返回成功不能代替 Git 推送、跨仓库合并、逐文件下载及 C 二进制执行。

GitLab EE 付费能力、OCI／容器镜像、其他制品协议、生产规模、物理宿主机及人工节省指标不在已通过证明范围。
