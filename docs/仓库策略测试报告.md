## 结论

本期“模板 → 预览 → 批量应用 → 结果核验与历史”已实现并完成核心验收。现有 46 项后端测试与新增 28 项策略测试，共 **74 项通过**。前端生产构建通过。真实 Gitea 1.26.4 完成 **30 仓库页面操作闭环**，每条规则的 **30 个有效字段全部一致**，未管理的 `archive/*` 规则保留。固定样本中没有误报成功或意外修改其他规则。

## 真实 Gitea 验收

批次 #2 由浏览器选择 30 个仓库、预览、查看字段差异并提交，最终页面显示 30 个“已核验成功”。独立脚本再次读取每个仓库的全部字段核对，正确率 100%；第一个仓库原有 `archive/*` 保留。每个仓库均为真实 Git 仓库，非模拟 API。

| 真实行为 | 结果 |
|---|---|
| 禁止直接 Push | 开发者推送 main 被 Gitea 拒绝，推送功能分支成功 |
| 双人审批 | 零审批、一人审批均不能合并 |
| 必须 CI | 两人审批但没有 `policy/test`、检查失败时均不能合并；检查成功后真实 PR 合并成功 |
| 禁止 Force Push | 普通推送允许时，非快进强推仍被拒绝 |
| 明确允许 Force Push | 经 Manager 更新模板应用后，同样的真实强推成功 |
| 签名要求 | 未签名提交被拒绝；Gitea 日志明确记录该提交未验证；关闭要求后同一提交成功。Gitea 客户端提示为通用内部错误，未据此误认网络故障 |
| 文件例外 | 禁止 Push 时 `docs/**` 文档可以推送，其他路径仍被拒绝 |
| 文件保护 | 允许 Push 时，修改 `blocked/**` 仍被拒绝 |
| 直接 Push 人员名单 | 有代码写权限但不在指定名单的开发者被拒绝 |
| 独立 Force Push 名单 | 同一开发者普通推送成功，强推名单不包含他时强推被拒绝 |
| 显式清空 | 推送名单、强推名单、CI 上下文清空成功，相应开启状态保留 |
| 安全预检 | 批次 #14：规则冲突、归档、跨组织团队、不存在仓库 4 个阻塞，已符合规则的仓库 1 个无变化；页面筛选准确显示 4 个阻塞 |
| 过期预览 | 批次 #15：预览后新增其他规则，执行阻断，新增规则保留；失败告警出现在现有顶栏 |
| 删除后的历史 | 删除 #15 使用的模板后，批次的模板快照仍然可读取 |

上述真实写入全部经 Manager 的预览和应用接口（30 仓库主批次由页面操作），故障注入仅发生在隔离测试仓库。辅助脚本为 `scripts/policy-real-fixtures.py`、`policy-real-acceptance.py`、`policy-real-boundaries.py`。

运行环境为 Apple Silicon 上 Docker 的 Linux amd64 兼容执行。批次 #2 从创建到完成用时 **437.743 秒**，其中提交后执行 **226.662 秒**。对应时段 Manager 来源的 Gitea API 完成日志共 **845 次请求**，秒级窗口最多 **2 次完成**；毫秒级调度间隔另由跨进程测试验证。该吞吐含人员、团队、分支预检和完整回读，不是单次 POST 吞吐。

## 人工操作减少的测量

建立 30 个独立 `manual-01`～`manual-30` 仓库，初始条件与批量样本的 main 相同。通过浏览器逐个进入 Gitea 原生设置，配置审批数、审批人/团队、Review 和 CI 等同一组有效保护规则，保存后独立回读全部有效字段。

| 指标 | 逐仓库路径 | 策略中心路径 |
|---|---:|---:|
| 仓库数 | 30 | 30 |
| 输入、点击或回车操作 | 690（每仓库 23） | 7（选择模板入口、输入搜索、搜索、全选结果、预览、展开差异、应用） |
| 连续自动化操作耗时 | 合计 83.323 秒 | 未单独可靠采集；后台全流程 437.743 秒 |
| 最终有效字段不一致 | 0 | 0 |
| 未管理规则意外修改 | 0 | 0 |

固定样本按交互次数计算减少 **98.99%**，剩余交互占比约 **1.01%**，达到“操作次数减少至少 80%”的目标。这里不包含两边共同的登录、一次性模板建立、人工阅读/思考，也不把自动化几秒输入全部字段当作真人速度。后台限速流程并不承诺比机器人逐项配置更快。**真人总工时减少 80% 尚未验证**。

首次自动化鼠标选择多选控件未正确落入原生表单，回读发现后整组数据作废，恢复隔离样本初始状态并用原生键盘确认重新执行。最终采用的 30 个样本全部通过回读。Gitea 原生页面会联动“取消过时批准”和“忽略过期批准”；前者启用后后者不再影响有效行为，按 Manager 同一归一化规则比较。

## 实际修复过的问题

1. Docker Desktop 宿主机共享目录的 `flock` 未正确排斥第二进程，运行中的预览被误判中断。独立进程探针复现后改用 Linux 原生数据卷，并增加启动锁自检；修复后 30 仓库双 worker 任务稳定完成。首次失败记录保留。
2. 分单元团队总体权限为 `none`，代码/PR 权限位于 `units_map`。修复权限判断并加入用户、团队和个人仓库回归，真实审批名单成功应用。
3. 空数据库双 worker 同时初始化存在建表竞争。初始化迁移加互斥，另起全新空库容器验证成功。
4. Nginx 原 Host 转发丢弃 5480 端口，影响同源检查；改为保留实际 Host。新增写接口在真实页面通过 CSRF 校验。
5. 源仓库切换期间旧规则结果可能停留，增加清空和请求身份检查；模板编辑增加数据库条件更新，避免并发覆盖。
