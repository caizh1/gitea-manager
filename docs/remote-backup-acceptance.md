# 跨网段备份恢复验收

本工具部署一台 Manager、两个独立 Docker 引擎及一台 Linux 路由器。被测后端来自运行目录内冻结源码构建的镜像；不向后端挂载工作区源码，不向两个模拟主机挂载宿主 Docker socket。

## 固定范围

- 增强版为 `gitea-enhanced:enhanced-20261020-r9`，数据库为 PostgreSQL 16.8；实际镜像摘要记录在运行目录。
- 地址默认使用 `10.231.10.0/24`、`10.231.20.0/24`、`10.231.30.0/24`，遇冲突自动选择新的三段网段。
- QEMU 为官方完整镜像，OpenSSD 为本地已提交历史的独立镜像。禁止浅克隆和将未跟踪缓存混入样本。
- 允许维护停机，完整业务迁移要求源业务设置保留；目标地址、端口及数据库连接等部署参数保留目标值。
- 测试结果为通过、失败、环境阻塞、未执行；未执行必测项不会被合并成通过。

每条命令可通过 `--run-dir` 指定已有运行目录；默认路径由 `work/remote-backup/latest` 指向。首次 `build` 冻结当前后端和前端，之后的 `build-driver` 只更新测试驱动镜像。开发中更新驱动后，需要重新部署驱动容器，不能误称旧镜像包含新检查。

新增入口是否实际运行，以 `results.jsonl` 为准。出现功能失败时保存现场，查明来源后再继续，不将本段命令清单当成自动通过保证。`process` 依赖独立停机检查点；保留失败现场可能需要额外空间，空间不足会停止，不能删除其他任务的数据。

故障也可按独立入口逐项执行：`ssh`、`address`、`storage`、`unsupported`、`concurrent`、`schedule`、`post-publish`、`network`。已有失败不因后续通过消失，互不依赖的阶段可以继续；涉及未知恢复状态时先实际接管，再执行依赖该实例的阶段。

可进一步使用 `archive-paths`、`storage-source`、`storage-manager` 分开执行小型归档安全、源临时盘及 Manager 盘故障。危险归档先有可导入的格式正向对照，再仅增加攻击条目；这些合成归档不会恢复到业务实例，也不能替代真实完整归档的正文损坏测试。

`database-source` 只执行源 PostgreSQL 不可用与额外客户端检查，不能代替导入中断。`archive-truncated` 使用真实完整归档的前缀，仅移除最后 4,096 字节后实际上传，不能以几字节假 ZIP 头代替。`process-source-snapshot` 由已停源的 snapshot 阶段触发强杀；先观察产品行为并保留原始结果，随后按唯一事务助手与指定备份运维命令验证人工接管。取得完整容器 ID，确认 API 主进程启动晚于原诊断，再停止并保留助手、启动原源及释放确认的空锁；不覆盖源数据，接管通过不等于产品自动恢复通过。

`process-source-dump` 和 `process-source-transfer` 对应另外两个只读备份阶段，沿用原源保留及指定任务接管保护，不借旧检查点覆盖源数据。导出用例还必须观察唯一新助手内实际的 `gitea dump` 进程，再中断 Manager；不是仅在进度名称出现时猜测导出已运行。执行前必须有足够真实归档空间且没有活动备份恢复。新入口存在不等于已执行，需保留完整阶段、进程、源健康和接管前后全表证据。

`manager-roles` 使用实际 TLS、隔离 LDAP 与 A/B 的真实组织目录测试组织角色。专属 TLS 代理只与冻结后端共享网络命名空间并转发到回环后端，不映射宿主端口、不修改产品或绕过证书验证。客户端校验独立 CA 与主机名，未信任 CA 必须失败；平台凭据和目录密码只在受限测试目录或真实 TLS 请求中使用。该入口仅需元数据六 GiB 余量，不能用于降低真实归档预算。

角色入口真实执行未授权登录、组织授权投影、跨组织/实例拒绝、敏感归档下载及备份恢复提交拒绝、撤权和停用后的会话失效。原九类管理业务逐字段比较，新建的专属目录及账号最后停用、授权撤销，原审计和组织核验记录保留，TLS 容器停止保留。它没有创建实际备份恢复，不替代完整角色矩阵、恢复后的权限迁移或运行中浏览器验收。

`manager-permissions` 为专属停用目录和账号保存独立 API 权限基线，接入通用 Manager 保留核验及普通完整迁移的任务前检查。真实反证只修改已停用账号的角色标志，要求判定器明确检出该字段差异，再通过原 API 恢复；始终不能形成可登录的临时平台账号。账号及目录不属于本夹具、仍启用或有授权时拒绝建立基线，不能用新采样覆盖未知差异。

完整角色复验会重新保存同一专属目录；只在复验与收尾均成功、其余 API 字段完全一致时，允许保存本工具导致的配置版本递增并生成新的独立基线，旧基线保留。这里比较公开 API 返回的全部专属目录与账号业务字段，不宣称覆盖隐藏密码密文或所有 Manager 数据表。审计追加及鉴权代次递增按真实操作保留，不做数据库回滚。

`seed` 前，在运行目录的 `seeds/qemu.git` 与 `seeds/openssd.git` 准备完整裸镜像，并保存引用基线。获取 QEMU 的官方地址为 `https://gitlab.com/qemu-project/qemu.git`。OpenSSD 使用 `git clone --mirror --no-local`，避免依赖源仓库硬链接。

## 隔离和证据

每轮资源带独立标签；清理前验证归属。`cleanup` 只停止并删除本轮 Compose 容器和网络，数据卷、凭据、备份及首败证据保留。删除数据卷应单独审核，不能通过全局 Docker 清理完成。

管理端口只绑定回环地址，具体端口见运行目录的私有状态。业务路径必须经过路由器；部署阶段验证路由关闭后两台模拟主机均不可达。故障控制器只接受固定操作白名单，不执行驱动传入的任意 Shell 命令。

原始证据保存在 `work/remote-backup/<运行编号>/`。该目录包含测试密码、令牌及敏感备份，权限应保持受限，禁止打入交付包或提交 Git。公开报告只包含脱敏结果和文件摘要。

`test-versions/` 保存每版驱动源码，`test-manifests/` 记录其镜像与文件摘要。重采集基线写入 `baselines/`，首次基线不覆盖。冷恢复与主 Manager 的任务证据采用不同文件名，避免任务 ID 相同覆盖证据。

隔离集成接收器提供真实 OpenLDAP、简化 OAuth 提供方、SMTP 接收和 Webhook 签名检查；它只接收本轮测试数据，不转发邮件。OAuth 提供方用于验证协议调用及迁移后的凭据，不证明生产身份提供方的可用性。

## 结果解释

`report.md` 和 `report.json` 汇总全部必测类别。测试驱动的细分证据可以先产生，但只有覆盖该类别全部约定场景后，才可将整个类别记为通过。首败不会因重跑成功而消失。

工具自身的安全回归为：

```bash
python3 -m unittest discover -s scripts -p test_remote_backup.py -v
```

源码存在、单元测试通过、模拟故障通过和真实跨网段恢复是不同证据。二十四小时稳定性、最终包复验、人工计时、物理断电及生产容量必须以实际完成记录为准。

稳定性任务持续发送带编号的评论和软件包，恢复后核对备份开始前已确认成功的写入。网络中断期失败的请求单独记录；未收到成功响应的操作不伪称已确认写入。`performance.json` 由原始采样计算耗时和停机估计，保留最大采样间隔，不能拿采样次数直接当停机秒数。

正式稳定性在开始写入前先预算十二份完整归档和下一轮临时副本。静态基线及独立检查点会等待原生启动统计与实际评论数一致；这不是放宽评论断言，原始统计和评论记录仍完整对照。Manager 存储注入只接受固定路径的有界临时盘，原数据库及备份卷保持，控制器持久保存原部署配置以便还原。

新版独立基线采集全部 public 数据表，不按业务表名白名单省略数据。仅使用已登记且有依据的精确字段排除项；旧基线的覆盖不能追认扩大。阶段同时保存宿主控制器摘要、源码副本及双时钟计时；睡眠空档保留为环境证据，不能压缩成连续稳定性或业务停机时间。测试阶段可防止空闲睡眠，但不会修改系统全局电源配置或绕过合盖行为。

`checkpoint-full` 保留既有停机归档，使用新名称保存完整往返基线；只将既存 unknown 操作的下一次核对时间设为到期，由原生启动任务真实追加审计。必须实际观察新增事件、全部原事件及完整范围保留，同时全表比较无其他差异，才可通过。两侧都通过后才切换后续故障使用的检查点，单侧成功不隐含另一侧通过。

本轮该入口于 2026-10-23 02:31:19 UTC 实际完成，两侧全部 150 表往返及各一条原生追加通过，独立原始行复核见 `docs/evidence/remote-backup-checkpoint-full.json`。它使用独立测试工具，不是 Manager 的恢复通过。接续还需同时检查实际进程和驱动容器内 `/evidence/test-run.lock`；实测宿主 `fcntl` 查询可能不反映容器内锁占用，不能单独用它推断空闲。

`load-pg17` 只使用本机已有的固定 PostgreSQL 17.11 镜像，导出配置及 RootFS 核对后加载到专属 B 引擎。`unsupported-pg` 使用全新独立数据目录启动真实 PG17 和空白 Gitea，要求实际回读主版本为 17、拒绝源 PG16 归档，并比较目标全部表未变化；退出时还原原 B 卷。它不修改实际版本字符串，也不把数据库连接错误当作主版本准入通过。入口存在不代表本轮已执行。


可用性计量修订：旧匿名版本接口的 401/403 不能判为停机，原证据保留但不生成 Gitea 停机估算。新版使用当前节点令牌的认证版本接口，记录 HTTP 状态和未知样本，凭据不写入测量；`storage-preflight` 对原不可写场景真实复验，并使用源容器 stop 事件独立核对停源。

`ssh-keys` 补齐源端独立 SSH 写用户、读用户、只读部署密钥、禁用账号和未注册身份，并实际验证 Git 读写或拒绝。成功后需重新验证源业务并采集基线；后续完整恢复检查复用相同断言，不能把源端准备成功当成迁移通过。

`manager` 不创建备份或恢复，只实际验证独立匿名与管理员会话、安全令牌轮换、跨站拒绝、退出后的旧 Cookie 重放、九类接口刷新和禁缓存，并核对既有真实失败任务、步骤及告警。前后管理业务数据逐字段比较。它是管理类别的部分证据，不能替代组织角色、运行中页面、并发或中断验收。

`manager-ui` 使用准备机已有的 Playwright 和 Chromium，通过真实浏览器点击冻结镜像的回环入口。可用 `REMOTE_BACKUP_NODE` 指定 Node，按实际安装配置 `NODE_PATH`；不会自动安装浏览器或下载依赖。执行前验证资源标签、冻结镜像、唯一回环端口、六 GiB 余量及同一执行锁，浏览器禁止访问其他地址或发送登录、退出以外的写请求。

该阶段覆盖未登录页面、真实失败任务的全部步骤与完整错误弹窗、告警列表、整页刷新、仅客户端断线时的明确提示及重新连接、其他核心页面、退出和重登，并保存前后九类 API 原始记录。截图、响应元数据和原始失败只留在受限 `browser/`；不保存 Cookie、认证头、密码或浏览器存储。它不注入路由器故障、不启动备份恢复，不能替代运行中任务、组织角色或跨网段网络矩阵。

`collaboration` 补齐源端 Issue、PR、评论的真实附件和下载权限、多次 Wiki 历史、普通用户收藏与关注、Issue 订阅、改名私有仓库的实际克隆，以及继续新增、编辑和删除评论。准备和实际写入后标记基线已变化，必须重新执行 `validate-source` 和 `baseline`；普通迁移在请求任务前拒绝尚未重采的基线。源端成功不计为恢复后的对应业务通过。

普通三轮与反向迁移预留四份 Manager 归档、三份独立下载及一份校验副本。并发、调度、发布后与网络分别在修改实例前预留整阶段后续归档，不能仅按第一份临时副本判断全阶段空间充足。


`validate-target` 在已经采用源样本身份的实际恢复目标上运行完整业务读写；有活动任务或仍是旧目标身份时，在写入前拒绝。开始即标记静态基线已变化；逐项通过和整体失败分别保留，不能把新增角色通过写成完整恢复通过。
