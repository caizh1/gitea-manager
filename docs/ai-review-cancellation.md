# AI Review 单任务强制取消

任务列表和详情提供“强制取消”，仅支持排队及分析中的任务。点击后确认一次；运行中的任务先显示“取消中”，实际停止确认后才显示“已取消”。发布、发布核对及其他结束状态不允许取消。

取消保留原始日志、诊断及已有结果，不发布本次正式审查意见。当前代码版本不会因后台扫描、模型配置或开关变化而自动重跑；新提交和人工重审可以创建新任务。中断后重新排队且已有执行记录的任务仍需核对停止，不能直接认定为尚未执行。

## 接口与执行保证

- `POST /api/ai-review/tasks/<job>/cancel` 使用现有登录、CSRF、平台与组织权限。重复取消幂等：取消中返回 `202`，已取消返回 `200`；不可取消状态返回 `409`，不存在或无权访问返回 `404`。
- Review 数据库迁移到格式 `14`，记录取消请求时间、操作账号、停止确认时间及异常原因。取消与进入发布由同一个 SQLite 写事务串行裁决；取消会立即撤销该任务的模型授权，旧执行者不能覆盖其状态。
- 独立取消线程每秒检查持久化请求，遵守升级维护标记；执行器失联时保留“取消中”，恢复后继续核对。任务执行锁确保准备线程退出前不删除工作区或启动下一条串行审查任务。
- 执行器持久化取消标记，拒绝迟到的启动请求；启动过程中取消不能重新创建进程。取消只终止本任务原生进程组及连接，回执不携带完整审查结果，避免大结果妨碍停止确认。
- 执行器进程重启后核对本任务工作区及原生命令，处理遗留进程；单独的 `404` 或网络超时不能证明停止。

源码准备中的下载和解包会检查取消。已收到响应头的静默下载可以关闭连接；尚未收到响应头的请求仍受现有连接与读取时限约束，期间保持“取消中”。正常原生审查进程的停止目标为十秒内；不能据此保证模型供应商内部计算已经停止。

## 验收与证据

使用独立项目 `gitea-review-cancel-20261014`、真实 Gitea 1.26.4 和 Linux amd64 候选镜像；模型协议替身仅用于制造静默等待，不评价模型语义质量。没有操作用户已有部署。

- Linux amd64 相关回归共 121 项通过；新增取消回归包含启动前取消、大结果回执、静默下载中断、取消与发布竞争、版本抑制、迁移和权限隔离。
- 前端生产构建和 23 项测试通过；真实页面验证列表及详情入口、确认弹窗、“已取消”、请求终止、未发布和诊断保留。窄窗口按钮采用正常文档流，没有重叠。
- 真实链路覆盖排队取消、模型等待取消、执行器失联恢复、Worker 重启恢复、人工重审、新提交自动触发六个场景；结果与耗时见 [验收数据](evidence/ai-review-cancellation.json)。标准版与兼容版 OpenCode 1.1.51 均通过六个真实场景；兼容版证据见 [兼容版验收数据](evidence/ai-review-cancellation-legacy.json)。全部场景没有发布正式 Review。
- 首轮全量 370 项检查中，三个测试仍断言旧数据库格式 `13`；已更新为 `14` 并回归其迁移行为。macOS 一次模型传输清理出现 `PermissionError`，诊断运行未复现；目标 Linux amd64 相应回归通过，未掩盖或改宽断言。
- 停止容器注入的第二轮出现一次宿主机 HTTP 连接重置，请求未到达取消接口且未落库；原失败保留在会话记录中。后续用暂停执行器验证失联时保持进程、不得提前确认取消，未降低取消状态或正式发布的断言。

## 人工基线与支持边界

目标用户为平台管理员和当前组织管理员，输入为有权操作的排队或分析任务。旧界面通过全局或仓库开关停止，单任务强停还需要人工定位会话、撤销授权、确认进程、核对发布与后续重跑；新界面是点击取消、确认两次操作，系统完成后续核对。

本轮六个固定真实场景全部通过，没有错误确认停止或额外正式发布；耗时按取消请求至任务终态计算。未采集真实人工操作工时、阅读及判断基准，**人工精力减少至少 80% 仍为未验证**，不能用两次点击或协议替身验收代替这个结论。

实际内网宿主机、模型供应商内部取消行为以及长期异常网络仍需部署后验证。只支持本项目既有单 Worker 串行审查、Linux amd64 和可靠本地持久卷。
