# 页面切换空白修复及同类检查

## 问题与修复

复现路径为“服务器管理 → 系统设置 → 服务器管理”，普通点击速度也会发生。系统设置原先在模板顶层并列放置接入按钮和内容容器，形成 Fragment；公共路由使用 `out-in` 退出动画，Fragment 移除时无法完成动画回调，后续页面一直停在空占位。地址和菜单高亮可以变化，但服务器页面没有挂载，因此不会请求服务器列表。

将接入按钮移入系统设置已有的根容器，保证该页面只有一个真实根元素。保留原有入口、表单、权限和页面动画，不修改服务器接口。

## 同类检查与验证

- 检查全部路由引用的页面以及登录页，共 21 个页面组件，并递归核对作为页面根节点的本地组件。只发现系统设置存在多个独立根节点。仪表盘的 `v-if / v-else` 分支互斥，组织仪表盘自身为单根元素，不是同类缺陷。
- 新增 `frontend/tests/routeRoots.test.mjs`：使用 Vue 编译器检查真实模板及所有根条件分支，防止 Fragment、无兜底的空根节点或不可确认的根组件进入动画。
- 新增 `scripts/test_route_navigation_ui.cjs`：使用真实前端页面和路由、固定接口替身及后台 Chromium；覆盖 29 个路由入口往返、两种动画偏好、四种点击间隔各三轮连续切换、慢请求中离开、接口失败后返回，以及组织管理员仪表盘分支。
- 21 项模板检查通过；源码与 Linux amd64 前端镜像分别通过 40 组浏览器检查，没有非元素根节点动画告警或未预期的页面渲染异常。
- 原问题的本地生产构建和源码共 6 次均复现；修复前的内存单根节点对照 3 次正常。修复后以上页面切换检查均正常。
- 前端生产构建通过。浏览器证据位于开发工作区 `work/route-navigation/`，不会打入离线包。
