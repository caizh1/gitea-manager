# PR diff 行内评论恢复

版本：manager-review-inline-20261015-r1，基于 manager-review-diff-20261015-r2。

人工基线是阅读文字报告、在 PR 中寻找对应行并复制意见。目标用户为现有 AI Review 使用者；本次减少的是重复定位和发布操作，不扩大模型审查范围。输入仍为固定版本的 PR 标题、描述和完整 diff；模型只调用一次，无工程读取工具，无第二次格式整理请求。

程序从 diff 严格解析新旧侧变更行，生成带路径、行号、原文的定位编号附录。模型在确定的问题段落中引用编号，程序核对编号与快照，再通过既有发布器提交正式 Review 和行内评论。报告是普通 Markdown，无强制 JSON 或 StructuredOutput；缺失编号、无效编号、未完整结束的报告、无法解析的补丁均保留报告，不因可选行内定位失败而重试模型。输入容量先检查原文，再生成索引；索引超限时省略索引，保留完整原文。

发布前重新从固定 diff 校验位置，发布后核对机器人、提交版本、评论集合、路径、侧别、行号及补丁片段原文。继续沿用发布结果冻结、分页、历史去重和未知写入不重放的机制。Manager 任务详情显示编号对应的位置和已有历史意见。

## 支持边界

- 支持普通修改、新增文件、删除文件、多个 hunk、空格路径和 CRLF；只对新增或删除的非空变更行发布。
- Gitea 1.26.4 对重命名文件按单一路径重算评论补丁，实测出现旧侧返回新文件代码；重命名意见仅保留报告。
- Gitea 截断带 `No newline at end of file` 的片段时会算错行号，实测把新侧第 2 行片段头计算为 `+0,3`；受影响 hunk 仅保留报告，其他 hunk 正常定位。
- 待确认事项、二进制、符号链接、子模块、无法唯一解析的补丁、未遵循定位格式的意见仅保留报告。行内评论数不代表缺陷总数。
- 发布后出现身份、版本或内容不一致时仍按既有机制报出核对失败，不重复写入；已生成报告保存在任务结果中。
- 旧审查不会自动补发评论；升级后新建审查生效。
