# 迁移制品隔离、完整清单与安全终止

接收协议八新增原生制品隔离及目标清单能力。Manager 在创建新任务前核对能力，接收端的新会话入口要求协议八；旧未发布任务保留现场，不自动重建新版基线或发布。已经发布的旧任务仅使用原有成功回执恢复路径。

本次试用包进一步修复终止时的查询错误降级：数据库读取失败直接阻断，确认不存在时才允许创建前收尾，且事务内拒绝旧逻辑接管新批次。已终止回执必须对应全部原生制品已回收。试用方式见 [真实环境试用说明](git-migration-trial.md)。

## 数据与权限

接收端先记录目标所有者、格式及规范化包名的占用，再建立原生制品。原生写事务检查该占用及批次状态；管理员通过普通制品接口也不能修改隔离内容。只有接收端创建、并在每次写入重新核对的任务作用域允许交接及回收。

内部制品回执保存实际包、版本、文件、内容摘要、元数据和属性的完整集合。来源附件清单保持原样；由源包提取的 NuGet nuspec 另外记录来源包及生成器身份。每次受控写入与回执、集合摘要一同提交，交接完成后冻结。恢复、准备、正式复检及发布不能将当前目标重新接受为基线。

NuGet 专用搜索、计数及分页应用相同隔离条件。通用文件摘要搜索和 Blob 授权仅使用可见包引用。共享内容仍可经其他可见包访问，不能据此获取隔离包的元数据。隔离期间的制品生命周期和下载审计保留为管理员实例审计，不通过群组审计或群组审计外送提前公开名称、版本和文件名。发布后的普通业务操作沿用原审计范围。

## 并发和恢复

单节点可靠本地持久卷上的批次文件锁覆盖交接、准备、发布和终止，跨进程生效，进程退出由内核释放。短数据库事务先取得治理锁，再取得批次和会话锁；内容暂存放在该事务外。

终止先保存 aborting，再逐包核验并原子删除原生引用和保存回收记录，最后恢复隔离仓库路径、归档并保存 abandoned。每个步骤均可在响应丢失或进程重启后核对重试；来源附件和历史记录继续保留。未知文件、回执损坏或归属不符阻断回收，不能用强制成功解除实例互斥。删除原生制品前还会核对来源封存清单，并在数据库短事务外重新读取来源制品附件的长度与 SHA-256；来源副本损坏时保留原生副本。原生附件修改与删除事务还会重新核对来源回执和批次状态，拒绝在途旧请求晚于封存提交；已终止任务的来源附件继续保留，已发布任务恢复原生附件操作。已安全终止后，原管理员仍可通过现有只读接口核验来源附件；该入口同时核对归档、隔离路径、批次及回收回执。

发布先完成时，后续原生业务写入按原权限执行；终止不得再次删除已发布内容。终止先成立时，整个批次继续隔离并禁止发布。

## 验收入口

- Python：`backend/tests/test_git_migration*.py`。
- Go：迁移接收器、制品模型和服务、治理模型、合并服务。
- 真实 HTTP：`scripts/git-migration-package-isolation-acceptance.py`。
- 既有完整清单矩阵：`scripts/git-migration-manifest-acceptance.py`。

本轮原失败、修复过程、SQLite 和 PostgreSQL 结果保存在 `work/package-isolation-20261030/`，不随部署包发布。真实 HTTP 验收包含六种格式、普通读取与写入账号、管理员写入拦截、两种 NuGet 来源形态、终止回执丢失、接收端重启及发布与终止竞争。

这些证据不代表生产宿主机、完整版本矩阵、任意规模、长时间持续负载或人工节省比例的验证。
