# 审查输入的无损文件分组编码

## 根因与改动

用户失败记录中的完整输入为 321,906 Token。任务冻结的输入目标仍为 65,536；即使使用当前 131,072 目标，甚至全部 262,144 上下文窗口，也不能容纳原请求。该记录的自动匹配确实使用了 `deepseek41`，不能归因为自动选择了错误计数器。

逐行证据原先重复携带路径、完整版本 SHA 和字段名。第七版新任务改为 `file-lines-v1`：相邻行共有的路径、版本和可选旧路径只保存一次；每行用固定列保存类型、旧行号、新行号、可评论标记和原始文本。逐行顺序、原始字符、空行、版本和位置均保留；模型输出协议不变，内部证据映射不变。没有删减变更、源码上下文或保护条件，也没有启用拆分。

第六版及更早任务继续原来的输入格式和计划；编码标记随新任务快照和执行单元冻结，已保存的旧单元不会因当前配置改变格式。

超额诊断新增实际输入计数和当次可用额度，经计数子进程传回、白名单过滤、持久化和页面显示。旧失败如果未保存实际计数，仍显示未知，不用当前配置猜测原请求大小。

真实测试还暴露了旧纠错提示的缺口：模型把评论定位到新增空行，原提示只说“位置校验失败”，第二次仍给相同位置。新任务的唯一一次位置纠错会附上全部无效位置、意见序号和确定性原因；不提供自动替代位置，不改动正文、级别、意见数量或顺序，返回后仍执行同样的严格校验。
