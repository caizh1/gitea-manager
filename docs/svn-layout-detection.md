# SVN 目录自动识别

当前默认入口已升级为“连接实例 → 自动发现项目 → 勾选并纳管 → 创建迁移计划”，见 [实例发现与项目纳管](svn-project-discovery.md)。本文保留高级指定布局的规则与上一版验收记录；普通纳管流程不再要求逐项填写 URL 或确认内部目录范围。

## 目标与验收边界

目标用户是添加、修正 SVN 迁移仓库的管理员。人工基线是用 SVN 客户端打开每个仓库、查找主干与分支及标签目录、判断迁移范围、填写三个相对路径，再通过预检发现拼接错误。新流程复用来源中加密保存的读取凭据，由独立执行器只读列举真实目录，标准情况无需手填路径，批量清单的布局逐仓库保存。

质量门槛：固定样本中明确布局的路径识别准确率为百分之百；多个候选、扫描不完整、读取失败和已变更来源的错误自动接受数必须为零。样本使用真实隔离 SVN，不把模拟目录字典当作实际协议验收。检测请求数、耗时与需要确认的比例单独记录。未经公司真实仓库与人工流程对比，不宣称人工精力已减少百分之八十。

支持标准目录、常用别名、大小写不同的实际目录、最多两层项目嵌套、同一地址下多个项目、整个登记目录作为单一主干。明确名称来自实际目录；未发现的目录不凭空拼接。任意命名的主干和复杂多项目结构可能无法唯一推断，这时从实际目录中选择，或把仓库地址缩小到具体项目。根目录整体迁移不能同时配置独立分支和标签，否则会把相同内容重复解释为不同角色。

## 操作

导入或编辑仓库时默认选择自动检测。填写清单后点击“检测目录结构”；唯一、明确的布局自动选中，不用填写三个路径。检测结果展示实际修订、主干、分支、标签和目录列表。多个项目、非标准目录或布局之外还有内容时，需要确认迁移范围；确认不代表可绕过扫描失败。保存后仍须重新预检，预检会检查当前源内容并生成新的不可变快照。

已有仓库可从“编辑仓库”重新检测并保存，旧预检自动失效，历史结果保留。高级手动配置用于已有明确布局的场景；普通流程无需使用。

## 运行边界

只在独立 SVN Worker 内调用 SVN，不在网页请求中启动 SVN，也不接触业务账号和权限。检测队列持久化，执行器中断后只读任务重新排队；升级维护期间停止写入。接口复用平台管理员授权、同源与 CSRF 校验，检测绑定来源版本、URL 与固定修订。保存只接受该检测实际读取过的目录；预检再次读取当前修订，来源或目录变化时不能沿用旧预检执行。

每次检测最多列举四十八个目录、两千个条目，单次目录请求最多三十秒，总体检查一百二十秒边界。未完成的扫描要求缩小地址，不生成可自动保存的结果。当前目录可见性受 SVN 账号权限限制；不能用检测成功证明账号能读取完整历史，正式迁移仍保留完整读取和停写确认。

目录名称只能提示角色，不能证明业务意图。已删除的历史布局、复杂目录级权限以及整个仓库根目录混放分支副本的结构，仍需完整预检与逐提交内容核验；不把猜测当作无损转换证明。检测不改动 SVN、不创建目标仓库。
