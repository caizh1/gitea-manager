# GitLab / Gitea 预迁移与正式启动门禁

## 使用流程

完成人员处理并达到百分之百后，进入“预迁移与检查”。没有人员映射需求的仓库可直接从盘点结果进入。页面显示两个独立结果：可执行性检查、隔离预迁移。两项均通过后，管理员确认来源项目与依赖全部停写，点击“复检通过后创建正式迁移任务”。服务端重新检查通过才创建任务；直接调用原执行接口无法跳过。

预迁移有独立编号和历史记录，不属于正式迁移任务。首次检查无需声明来源已经停写，但来源写入会使结果失效。系统先在管理员隔离区导入，再将仓库准备到最终群组，安装最终规则并按原生协议核对制品。接收端整批隔离门禁持续禁止普通账号、Actions 和搜索访问。正式任务复用同一批已核验仓库，全部复检通过后原子开放，避免重复转换、重复导入和编号变化。

## 检查范围

| 检查 | 验证方式 | 失败处理 |
| --- | --- | --- |
| 输入与人员处理 | 固定盘点摘要、映射版本、目标身份、有效群组权限 | 重新盘点或完成人员确认 |
| 接收能力与路径 | 接收协议、管理员、群组稳定编号、授权摘要、同名路径冲突 | 配置接收端或选择无冲突群组 |
| 来源可读性 | 完整读取身份和版本；独立来源清单与盘点比对 | 修复读取权限，不忽略无法读取的资料 |
| 容量与可写性 | Manager 与目标磁盘的字节、inode、实际文件写入和数据库写入；演练期间持续监测 | 补足资源后从原检查点继续 |
| 代码与文件 | Git 引用、LFS、Wiki 历史；附件、制品和日志的实际传输与目标回读 | 保留隔离现场，提示具体失败步骤 |
| 转换覆盖 | 逐项比较对象、文件、保护规则清单；不支持的合并条件与资料阻断 | 补齐接收能力后重新预迁移 |
| 最终复检 | 再查来源、账号、权限、目标路径；重新克隆代码/LFS/Wiki、回读原生对象及附件 | 不创建正式任务，列出阻断项 |

规则、原生制品和最终归属在预迁移中实际准备并回读。整批发布凭证固定全部仓库的规则、单元、历史对象和群组修订；开放时再次核对凭证。任何仓库失败都不开放整批。源端未提供文件长度时，演练实际下载后重新计算容量，仍存在未知长度则不能通过。

## 状态和恢复

- 通过结果有效三十分钟；人员确认版本、盘点内容或目标身份改变会失效，正式启动仍须实时复检。
- 排队、运行、通过待确认、阻断及中断状态均保留来源和目标实例互斥。备份、恢复、其他迁移和实例修改不能绕过。
- 检查列出已通过项、阻断项、来源范围和处理建议；不把“已通过检查数”称为成功概率。
- 目标令牌失效时，可更新同一管理员的新令牌；身份改变会被拒绝，恢复凭据不释放实例互斥。
- 失败或执行器中断后，可从同一检查点继续；结果过期后必须重新检查和确认停写，不能沿用旧确认。创建或开放回执丢失时，核对原批次的服务端状态，不能按同名接管或重复发布。
- “结束预迁移并保留现场”关闭本批次接收会话，将尚未开放的仓库和原始文件收回管理员归档空间，再释放互斥。已开放数据不接受此操作。升级维护仍阻止写入。

## 保证边界

检查通过证明当前可读取快照在支持范围内完成了检查和隔离导入，不是对未来故障的绝对保证。网络、磁盘、外部管理员操作和源系统未暴露的数据仍可能影响正式执行。因此保留停写确认、启动前复检、交接后回读和失败隔离，不显示未经统计证明的“迁移成功率”。

本功能不扩大原迁移支持范围。OCI 暂不包含；GitLab EE 付费能力继续标记未验证。不能把有限隔离验收写成全部版本、生产环境或减少人工百分之八十的证明。人工基线是逐仓库人工导入并逐项核对代码、文件、人员和规则；实现把这些重复核对合并成自动检查，实际企业规模的耗时和人工介入比例仍需实测。

验收入口：`scripts/git-migration-preflight-acceptance.py`，测试包含真实附件、制品、LFS、来源变化后的拒绝、结束归档、重新盘点、复检与完整交接。人员整批回归继续使用 `scripts/git-migration-retention-acceptance.py`。
