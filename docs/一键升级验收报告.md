## 结论与环境

工程验收通过。使用独立项目 `gitea-oneclick-acceptance`、真实官方 Gitea 1.26.4、带历史数据的旧 Manager、Linux amd64 镜像和离线 OpenCode 1.18.7。旧 Manager 数据包含服务器、管理员密码、备份记录与文件、定时任务；后续又加入已加密的模型与机器人凭据、审查历史及反馈数据集。

## 操作与耗时口径

目标用户为已经维护 Manager/Gitea 的部署管理员，输入为已有可靠部署及管理凭据、内网模型地址/Key、需要接入的仓库；模型、权限或回调验证不通过时，不新增启用状态。验收不允许误报升级成功、丢失旧记录、重置密钥、重复创建机器人或把未通过检查的新仓库启用，上表样本均满足这些要求。

以旧版人工执行“基础 Manager 升级并首次增加 AI 能力”的检查清单为基线，共 32 项人工处理事项：

1. 系统架构、包校验、空间、在途任务、项目名、端口、持久挂载：7 项。
2. Manager 库、Review 库、配置、密钥、旧镜像备份：5 项。
3. 主密钥、执行令牌、缺失服务参数、三类主机名单：6 项。
4. 镜像导入、服务启动、健康检查、历史核对：4 项。
5. 机器人创建、仓库只读权限、限定 Token 生成、Token 录入：4 项。
6. 模型地址、模型 Key、仓库选择、Webhook 安装、进度组件安装、检查后启用：6 项。

标准新流程为运行升级脚本、填写模型地址、填写 Key、选择仓库、点击检查并启用，共 5 项；清单计数减少 **84.4%**。这是操作清单对比，不是对真实用户阅读、判断和点击时间的测量；多实例选择、不可回连地址修正及异常处理需要额外操作。后续升级通常只需运行脚本。
