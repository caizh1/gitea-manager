# 外接审批规则候选版使用与接入说明

当前状态：功能开发与隔离验收候选，正式强制接入未发布。APR-RACE-001 为 P2 已知失败、暂缓修复、后续必修。不得宣称等同 GitLab 企业版完整审批能力。

## 当前支持范围

- 官方 Gitea 1.26.4 Linux amd64；Manager 中新增独立表，不改 Gitea 数据库或源码。
- 时间线完整性目前通过既有 Docker/SSH 运维连接读取 PostgreSQL 标记，使用只读事务及短超时；不读取评论正文、不增加权限、不改数据库结构和历史。数据库与运行中 Gitea 连接必须一致；其他数据库类型尚未完成适配，会停止预检。
- Manager 导航“审批规则”：选择实例、组织和已有仓库；设置明确分支、总票数、稳定团队 ID 与每组票数。
- 默认三名不同合格用户、两个必需组各一票。跨组人员满足两个组，总数只计一次；作者不计票。复用原生批准和撤回，新代码需要重新批准。
- 同仓库一份配置；目前仅明确分支名、组织仓库，不接受新增规则通配范围。不足资格、审批池排除组、直接推送和管理员覆盖等不兼容配置只报告冲突，不修改原生设置。
- 原生审批、CI、冲突、签名等仍自行执行。新增面板的“最近核对：新增要求已满足”不是最终合并授权。

## 规则预检和安装

1. 保存规则，执行“接入预检”，核对现有保护、组身份、PR 清单和待验证项。预检不修改 Gitea。
2. “安装组件”导出影子包。提供 Gitea 宿主机可访问的 HTTPS 门禁服务地址，结尾 `/api/approval-internal`。包中包含安装凭据，目录 0700、文件 0600，不能放到网页公开目录。
3. 在 Gitea 宿主机运行包内 `python3 install.py check --container 实际容器名`，保存现场预览。发现只读挂载、异常路径、非官方版本、无兼容包装器等即停止，不修改容器挂载或重建 Gitea。
4. 核对预览后执行 `install`。只替换唯一受管 Hook 文件，临时文件在扫描目录外，保留原包装器和其他 Hook。全实例页脚增加唯一组件片段。写入前校验当前摘要；并发变化则停止。
5. 现有代理需要将 Gitea 同源 `/-/manager-approval/` 转发到 Manager **前端入口**的 `/api/approval-view/`，由其 nginx 分发到独立 `approval-view` 服务；不要直接转发到主后端端口占用门禁工作进程。保留 Cookie、禁用代理缓存、仅接受 GET。代理只允许使用其已有的无中断重载机制；当前安装器不会擅自改写代理。
6. 安装器重载模板并读取真实运行时标记。另行登录真实 PR，验证当前账户权限、票数、错误状态和持续业务。安装回执不能代替这一步。

影子包装器直接退出成功，不等待外部服务。强制配置仅在验收工具创建、具有匹配实例标签且 Manager 进程显式绑定的隔离容器中提供。生产强制启用接口始终拒绝，不存在浏览器传入测试标志的跳过方式。

## 状态与恢复

- 草稿/已停用可编辑；已安装规则先停用并卸载门禁后编辑，防止更换版本使旧包失去回退凭据。
- 导出后进入待安装，不代表保护有效。准备状态不允许再次导出更换令牌；磁盘状态或回执不确定时先核对现场。
- 回执丢失时使用原包 `verify-installed`：重新核对配置、程序、Hook 和运行时，补回执而不重复写入 Hook。
- 安装目录锁残留时需人工核对是否仍有任务执行及文件实际状态；不能无条件删锁重装。
- 审计记录共享管理员操作，不伪造个人操作者。原生 PR 页仍使用 Gitea 自己的登录身份；管理令牌不进入浏览器。
- 展示服务逐请求通过原生接口验证 PR 权限和当前登录人。同一 PR 的计算结果最多复用两秒，保留原核对时间；原生更新时间、关闭状态或配置变化使快照失效。浏览器还要匹配页面代码版本，界面展示的是最近核对结果；无浏览器身份进入共享缓存。门禁始终重新读取原生数据，不以展示快照放行。
- 独立展示服务只接受展示读取及健康检查，不注册规则管理、安装回执或 Hook 校验入口。其故障不能重启主 Manager 或 Gitea；升级时与其他 Manager 数据写入者一起冻结、核对和恢复。

## 分开回退页面和门禁

页面回退使用 `uninstall-ui`，只移除本组件全实例页脚片段，保留其他组件与管理员更新，不改变门禁状态。此操作影响该实例所有仓库的扩展面板，应在变更预览中明确。

门禁回退先在 Manager 记录停用原因，再使用原包 `uninstall-gate`。停用待完成期间受管新 PR 仍拒绝合并，直到受管 Hook 确认移除。只移除本仓库两个受管 Hook 及已停用凭据，不改其他 Hook、原生保护、Git 引用或业务历史。旧 PR 的本地豁免清单不新增远程依赖。

模板与文件比较替换可以发现预览后和写入前的变化；非协作管理员恰在最后摘要校验与重命名之间写入的极短竞争仍待故障验收，不承诺绝对无竞争。不要通过恢复整个页脚或数据库掩盖安装失败。

## 内网测试包之外仍待完整验收的部分

自动合并五种方式、SSH/HTTP 及多项原生保护已有分项通过证据，详细范围见矩阵记录。并发创建 PR 的切换边界、所有安装中断点、非协作管理员极短写入竞争、真实后台任务共存、全部代理兼容、跨标签页压力及审计保留容量、双 24 小时、现场峰值两倍负载、现场接入与 80% 人工精力指标仍需执行或开发。按用户最新安排，先交付功能测试包，多用户并发及长测在发包后继续；不宣称完整矩阵通过。

当前预检双读 PR 清单只用于隔离静止切换样本，不能证明繁忙生产的原子切换。Hook 的最终检查后撤回/移组窗口未修复，发布门禁继续阻断。

## 复现与交付

- 后端测试：在离线后端镜像中执行 `python -m unittest discover -s tests -q`。
- 实际集成：`python3 scripts/approval-integration.py`，自动创建本次隔离容器、数据和原生规则，不接受生产地址。所有业务合并写请求仅发送一次，先只读等待原生冲突检查就绪。
- 旧竞态：`scripts/approval-feasibility.py` 及原始证据保持，退出码和原断言不能改成通过。
- Go Hook 用静态 Linux amd64 编译；真实 Git 对象测试在官方 Gitea 镜像中运行。
- 候选包按项目标准包括前端 dist、后端 wheels、官方镜像和固定 Manager 镜像、脚本、中文文档。校验值和实际验收层次分别记录。
