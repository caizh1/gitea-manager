# 仓库策略后续待办

组织模板、组织内手动批量下发、稳定身份与明确跨组织复制已实现。以下功能不在当前完成范围；组织范围筛选不是多用户权限隔离，批量下发也不是原生强制继承。

| 待办 | 依赖 | 验收条件 |
|---|---|---|
| 多用户登录、角色权限、组织和仓库隔离 | 真实用户身份、组织成员同步、授权模型、会话与审计迁移 | 管理员、模板维护者、应用者、只读者分别验证；越权 API 和跨组织访问被拒绝；审计可归属个人 |
| 集团模板发布、授权应用和强制治理 | 上述权限、发布审批、豁免与紧急变更流程 | 未发布模板不得用于强制治理；范围授权可追溯；豁免有责任人与期限；紧急操作可审计 |
| 独立漂移检查与单仓库/批量修复 | 模板与仓库绑定、期望状态、差异引擎扩展 | 人工修改、规则删除和规则增添均按覆盖边界准确识别；只修复获准范围；零误报成功 |
| 自动巡检与漂移告警 | 独立漂移检查、可恢复调度、限流与告警去重 | 千仓库分片巡检不压垮实例；重复漂移不刷屏；修复后关闭告警；中断续检可验证 |
| 新仓库自动纳管与持续同步 | 组织到模板的持久绑定、新仓库事件/轮询、审批与排除规则 | 后续新增仓库按明确授权纳入；改名、转移、重复事件和停机补偿均有证据；不能静默覆盖未授权仓库 |
| 跨实例模板复制及人员团队映射 | 显式身份映射、版本能力探测、兼容字段矩阵 | 同名异人/异团队不自动关联；每种支持版本均完成真实行为验收；不支持字段明确阻断 |
| Commit Message 门禁纳入策略 | 复用现有提交门禁服务，明确定义 Git、网页编辑与 PR 合并覆盖范围 | 同一规则的安装、检测、移除及失败回滚均有审计；不把 Hook 安装成功当作执行成功 |
| CODEOWNERS | 路径匹配语义、仓库文件变更机制、审批流程 | 通过受审查的 PR 更新文件；正确处理文件优先级、失效人员和团队；真实 PR 验证审批行为 |
| Webhook | 密钥托管、回调地址授权、事件配置适配 | 密钥不进入日志或模板明文导出；重复应用不新增重复 Hook；签名回调与失败告警通过测试 |
| CI 模板 | 流水线文件版本、执行器能力、变量与密钥边界 | 通过 PR 安装；不会覆盖项目自定义内容；真实运行及状态检查绑定通过测试 |
| 模板版本与批量升级 | 后续明确的业务需求、发布与回滚语义 | 届时再设计不可变版本、仓库使用状态及升级流程；当前内容哈希仅用于并发校验，不是版本管理 |
| 多节点 Manager 与任务控制 | 共享协调服务、租约栅栏、任务取消及历史归档 | 故障转移不重复执行；取消有明确边界；历史归档不影响审计；真实多节点压测通过 |

所有扩展继续使用确定性预检、差异、写后回读和失败隔离。引入模型辅助能力前，必须针对实际部署模型和真实样本单独定义准确率、误报/漏报、人工介入指标；第一期不依赖模型推断。
