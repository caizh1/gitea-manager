# SVN 多来源迁移

迁移中心支持保存多个 SVN 来源，选择不同来源的仓库，生成计划并由独立执行器逐仓运行。本期迁移文件和历史，保留作者署名；不创建业务账号、不导入 SVN 权限。

## 使用流程

1. 平台管理员打开“SVN 迁移中心 → 来源与仓库”，添加实例名称、地址和完整历史读取账号，点击“连接并发现项目”。英文标识自动生成，可在高级设置修改。正常流程不需要填写项目 URL。
2. 系统读取当前账号可访问的实例列表，逐项验证 SVN 目录身份。勾选一个、多个或全部项目，点击“纳管所选项目”，直接创建迁移计划；不再要求确认项目内部范围。`test_spec` 等普通目录属于原项目，不另拆仓库，不默认排除。实例未开放项目列表时，页面提供“补充项目地址”备用入口。完整流程、目录保留方式与支持边界见 [实例发现与项目纳管](svn-project-discovery.md)。高级登记和旧版指定布局仍保留，但不属于默认流程。
3. 可导入作者 CSV，表头为 `source_id,svn_user,name,email`。没有映射的作者使用原署名和以来源身份生成的 `.invalid` 历史邮箱。同名作者不跨来源合并，后续授权也不会自动改写这些提交。
4. 检查预检问题。遇到 externals、引用重名、不支持布局或读取失败时，调整输入或明确排除该仓库，再重新预检。排除清单会保留在执行报告中。
5. 来源管理员先备份 SVN，确认账号可读取全部迁移范围及其历史，再停止所选仓库写入。重新预检后，在页面确认完整读取和停写，提交执行。
6. 执行期间可以离开页面。执行器逐仓转换、逐提交核验，再创建私有目标并推送，最后重新克隆核对。暂停在当前仓库完成后生效；取消会停止当前子进程并保留现场和远端资源。
7. 迁移完成后下载报告。业务成员和权限在 Gitea 中另行配置；目录读取隔离需要拆仓，CODEOWNERS 仅适合配合分支保护实现审核流程。

目标仓库推送前关闭 Actions，避免导入的历史工作流自动运行；工作流文件本身仍完整保留，完成迁移后由管理员按需启用。

## 页面与记录

- “迁移工作台”每行是一个计划，可以包含多个来源的多个仓库；状态与待办按该计划展示。预检通过后仍需确认完整读取和停写。
- “来源与仓库”左侧选择来源，右侧查看仓库。勾选在当前登录会话内跨来源、跨页面保留；退出、切换身份或整页刷新后重新选择。迁移结果和最近预检分列，后一次失败不会抹掉以前成功迁移的事实。
- 工作台与来源页使用相同预检编号进入共用详情。每次重新预检生成独立记录，详情可以前后翻阅历史；输入变化后旧记录标记为需重新预检。升级只能保留旧版仍存在的最后一份预览，无法补回此前已经覆盖的内容。
- “执行记录”每行是一次实际提交的任务。执行详情有独立地址，刷新仍查看同一任务；显示固定快照、真实仓库顺序、当前阶段与活动。只对可测量的提交核验量显示阶段进度，不估算总百分比或剩余时间。
- 提交回执丢失时，在同一确认窗口重试会沿用幂等标识。重新打开窗口前先检查执行记录，避免把已提交任务误作未提交。

## 初始权限与恢复

新页面在创建计划时明确选择目标群组，支持已有根群组与子群组，并预览完整仓库路径。迁入仓库保持私有，沿用所选群组现有授权，不修改成员或共享；群组身份和授权变化时阻断并要求重新预检。旧客户端与历史快照继续使用独立私有根群组，只有 Manager 已记录且仍仅有迁移管理员访问的群组才允许自动复用。详见 [目标群组与入口发现](svn-target-groups.md)。

目标默认必须不存在。建库和推送前记录意图；写入回执丢失后，按任务标记、目标 ID 和全部引用核对。不能核对时显示“待确认”，不覆盖已有内容、不自动删除资源。恢复必须使用原快照，源和目标配置变化需要重新规划。

成功任务可以显式清理本地工作区；数据库中的迁移结果、逐提交映射和审计仍保留。失败和待确认的现场不能自动清理。取消后再恢复也会重新占用来源和目标，防止不同批次接管同一仓库。

## 部署与持久化

独立服务名为 `svn-migration-worker`，镜像为 `gitea-review-svn`。构建文件为 `backend/Dockerfile.svn`，包含 Git、git-svn、Subversion、Python 和 CA；最终离线包携带预先构建的镜像，不要求部署机联网安装依赖。

执行器只挂载 Manager 数据卷，不挂载 Docker socket 或主机 SSH 密钥。SQLite 数据库、`svn-migrations/` 工作目录、`svn-migration.key` 必须放在同一个可靠的 Linux 本地持久卷。Docker Desktop 验收使用原生命名卷；不支持多节点或无法可靠执行文件锁的共享文件系统。

来源密码加密存储，临时解密文件仅在任务期间存在。升级必须保留原迁移密钥；已保存加密凭据但密钥缺失时拒绝生成替代密钥。升级入口会检查迁移中的任务，并在安全停机后备份数据库、工作现场和密钥。

## 内容边界

- 支持 `https`、`http`、`svn` 来源；暂不接受 `file` 或 `svn+ssh`，页面不能指定主机文件路径或命令。
- 支持固定修订的主干、分支和标签，以及 git-svn 保留的删除/替换历史引用；不做持续增量同步。
- 当前或扫描到的历史目录属性存在非空 `svn:externals` 时阻断，避免遗漏外部内容。
- 对转换出的每个提交核对文件集合、SHA-256、可执行位、符号链接、作者、时间和日志。随后重新克隆目标并核对引用和对象完整性。
- 从 SVN 变更记录反向核对导入覆盖，文件变更、带文件的目录复制和删除不能静默缺失；报告逐修订列出映射路径及空目录、属性操作等未生成提交的原因。
- 空目录和不能转换为 Git 机制的 SVN 属性保留在报告中。合并后的内容可以保留，但不承诺恢复 SVN 的全部合并关系为 Git 多父提交。
- 完整性依赖来源账号能够读取所声明范围的全部内容；连接成功和可见历史一致不能证明不存在管理员未声明的隐藏内容。
- 未得到真实 SVN 样本、生产规模基准与人工计时前，不宣称生产环境已验收或节省人工达到 80%。

## 验收命令

`python3 scripts/svn-migration-acceptance.py --image <本次固定镜像标签>` 创建独立标记的三个 SVN 服务、增强版 Gitea、Manager 和 Worker，并通过真实 HTTP API 驱动九仓库迁移。输出保存在 `work/svn-acceptance/`，不打入交付包。该目录含随机测试凭据，应按敏感数据保管。

转换逻辑从 `gitea-enhancement` 的 `b8232258ee` 迁移工具整理，运行时不依赖相邻仓库。旧工具的历史验收结果不能替代本模块的验收结果。
