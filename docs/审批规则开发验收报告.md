## 已实现的工作闭环

Manager 保存稳定仓库/团队身份、规则、预检快照、存量清单、接入状态、随机请求去重及审计。管理入口支持创建、编辑、预检、导出影子组件、PR 检查、执行记录和申请停用。编辑已安装规则前须先卸载门禁，防止丢失回退凭据。重复导出和并发状态切换均有校验。

原生批准票通过当前资格、最新正式决定、撤回、代码 SHA 与代码变更事件核对；总数按人去重，指定组分别计票，作者不计票。原生要求独立执行，预检不会改写原有审批池或分支保护。当前新增范围只支持明确分支名称、组织仓库和新代码重新批准，不等于全部 GitLab 企业规则类型。

影子 Hook 不进行远程等待；隔离强制 Hook 在最终引用更新阶段绑定仓库、PR ID、序号、目标引用、旧目标及待写代码，并核对实际 Git 合入树。存量豁免使用本地 ID 清单。最终检查后撤回/移组的已知窗口保留，不以重复查询掩盖。

PR 面板复用 Gitea 登录会话，浏览器不持有管理令牌。显示总人数、逐组人数、批准人员、更新时间、存量豁免和原生要求。过期、失败、身份和代码变化时移除通过提示；关闭页面显示当前规则核对不代表历史授权。原生审批和合并按钮保持。

安装使用扫描目录外暂存、摘要和属性快照、独立目录锁、原子重命名、保留包装器和其他 Hook、模板片段合并、热重载与真实页面标记核验。回执丢失有仅核验补回执入口。页面回退与门禁卸载独立，后者需先记录停用原因；保留接入后新增业务数据。

## 首次失败、修复与回归

详见 `审批规则开发首次失败记录.json`。保留了隔离模型夹具必填字段缺失、官方团队 organization 为空、INI 全局键、变量形式 Hook 包装器、缺 Git 的编译镜像、原生冲突检查尚未就绪、Docker 容器名约束及关闭 PR 页头字段缺失等首次问题。

原生拒绝后会重新检查冲突。测试读取 mergeable 直到就绪，再发出一次合并请求，不重复提交合并写请求，不把原生“请稍后”误当成组规则拒绝。关闭 PR 展示修复已通过最终固定镜像真实页面回归。

网页测试中，带未提交测试草稿的原标签页在拒绝后停留加载状态，工具刷新未产生导航；新标签页可显示原生拒绝详情，并成功执行补票合并。该现象保留为原生表单导航/浏览器交互待复核项，尚不能宣布“正在提交表单”的整个接入子用例通过。

APR-RACE-001 的原始 25 个可行性用例中，10 个最终撤回/移组失败仍保持已知失败。没有删除原断言、转换成通过或从发布统计隐藏。
