# 发布结果待核对：评论补丁空侧坐标修复

本次修复包基于已冻结的 inline r2，只更新后端评论片段校验文件。前端与执行器沿用该版本的固定镜像；不混入工作区其他功能。

## 故障与根因

现场返回的错误为“Gitea 评论片段与固定 PR diff 不一致”，任务状态为 `publish_unknown`。再次请求核对只表示核对入队，不能代表核对成功。Gitea 已存在本任务 Review 时，“确认未发布”会拒绝解除阻塞，避免重复发布。

已在独立的官方 Gitea 1.26.4 中复现同类确定性缺陷：连续替换十二行，评论位于新侧第五行时，Gitea 返回 `@@ -13,0 +2,4 @@` 及新侧第二至第五行。固定 diff 此时的旧侧游标为十二；Gitea 截取函数使用下一行游标十三，而空侧长度为零，导致现有校验器把正确内容判为不一致。旧侧第五行也会对称地返回 `@@ -2,4 +1,0 @@`。

Gitea 源码中的 `CutDiffAroundLine` 在截取后使用游标重算起点；空侧没有源码行可供回退，因此保留了下一行位置。此现象已由真实服务回读确认，不只依据源码推断。用户现场的实际评论片段尚未取得，不能断言其唯一原因就是该样本。

## 修复边界

仍先按原始坐标核对。仅当片段一侧长度为零、固定 hunk 原来确实包含该侧源码，且固定 diff 能证实首行坐标只差一个空侧游标时，校正空侧坐标一行。

有源码一侧的行号、路径、新旧侧、问题行、连续顺序及每行正文仍逐项核对。错误正文、错误问题位置、超出计数、其他坐标偏移仍拒绝。纯新增和纯删除文件不使用该兼容分支；重命名和无文件尾换行的既有降级规则保留。

不清理远端评论，不把真实不一致标为成功，不重跑模型，也不修改任务发布内容。升级后由“核对发布”只读回查已有 Review，匹配后解除阻塞。

## 验收基线与结果

目标用户是遇到此类发布阻塞的 Manager 管理员。人工基线是查找原 Review、对照每条评论与原始 diff，再处理队列。支持输入为已有固定 diff、任务发布结果及可访问的官方 Gitea 1.26.4。质量门槛为有效样本全部核对通过，固定反例全部拒绝，核对期间零新增评论，后续任务可领取。

- 修改前的 inline r2 在真实十二行替换样本上失败，错误与现场一致。首次故障、错误镜像基线导致的统计断言失败分别保留，没有修改旧断言来通过验收。
- 当前工作区相关七十七项回归通过；固定交付镜像内相关四十八项回归通过。
- 独立官方 Gitea 1.26.4、真实 Git 提交与 PR：十五条行内评论回读通过，包含替换块两侧的中部和末尾、新增、删除、多 hunk、空格路径与 CRLF。
- 注入“远端正式 Review 已存在，本地仍待核对”后，确认后续任务无法领取；只允许 GET 的核对成功后，阻塞消失、后续任务可领取，Review 数量不变。分页发布恢复、历史去重和版本变化保护继续通过。
- 前端生产构建和四个修改文件的语法检查通过。修复包复用 inline r2 前端与执行器，未引入其他界面改动。
- 离线升级包的归档摘要、逐文件清单和运行数据排除检查通过。用包内升级器将独立 inline r2 实例升级成功，耗时五十一点五一九秒；维护期间持续轮询，升级后原登录 Cookie 可恢复。
- 从最终归档导入的后端镜像与源码摘要一致；再次在独立官方 Gitea 中通过十五条真实行内评论、未知发布只读恢复和后续队列解除验证。验证记录随包目录保留。

上述为固定样本的工程链路验收。实际现场评论、目标主机恢复、其他 Gitea 版本、模型判断质量与人工精力减少百分比尚未验证，不能宣称达到人工精力减少百分之八十。
