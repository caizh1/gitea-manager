# 历史 Manager 离线升级

适用于 Linux x86_64、Docker Compose v2 和 SQLite 持久化部署。升级已有 Manager，不替换 Gitea 或 PostgreSQL。保留原项目、服务端口、数据库、管理员账号、服务器地址与令牌、SSH 挂载、备份文件和定时计划。旧版尚未区分连接方式时，已有 is_local=true 记录转换为本地 Docker，其余沿用 SSH，不根据容器同名猜测目标服务器。

## 操作

将本目录复制到服务器的新目录，不要覆盖原部署目录。保持 upgrade.sh、gitea-manager.tar.gz 和校验文件在同一目录。

先检查：`sudo bash upgrade.sh --check`

执行升级：`sudo bash upgrade.sh`

多个 Manager 实例时会列出选择；也可明确指定：`sudo bash upgrade.sh --container gitea-manager-api`。运行期间保留终端，暂停新的备份、恢复和审查操作。不要执行 install.sh、uninstall.sh、deploy.sh 或删除数据卷。

升级器会校验包与镜像、检测执行器、检查在途任务和空间，随后冻结 Manager、备份旧数据及旧镜像、启动新版并逐表核对旧列和旧记录。旧备份文件留在原路径，核对文件大小和时间。首次新增 AI 能力只初始化独立数据卷，不要求提前填写模型密钥。升级成功后仍用原页面地址和管理员密码登录。

## 连接与配置

服务器管理中检查本地与远端记录。原有 SSH 私钥和挂载保留，不生成新 SSH 密钥替换原连接。旧实例没有本地标记时保持原 SSH 方式；需要改为本地 Docker 时，在管理接入页面核对实际实例后设置。

本包包含此前的 1.27.3 准入、默认 210000 Token 压缩阈值、取消 200 行限制和模型连接测试详情。标准与兼容执行器均在包中，停服前先运行真实启动检测。真实模型密钥在升级后通过页面配置与连接测试，不打入交付包。

## 回退与边界

升级期间普通失败会自动恢复旧镜像、旧数据库和旧配置并检查原服务。原部署目录下 .gitea-manager-upgrades 保存私有备份和阶段记录；请保留，不要发送含密钥的完整记录给他人。成功后使用 compose.managed.json 维护新版服务，不要用原 Compose 重新启动旧服务。

成功并恢复业务后，不自动覆盖数据库回退，以免丢失新增数据。断电、Docker 守护进程退出或强制终止可能留下执行锁，应按阶段记录恢复，禁止直接删锁重跑。外置数据库、非持久化数据库、应用源码覆盖挂载等不支持的部署会拒绝升级。

本轮基准使用仓库历史提交 948b4c0 的真实后端代码和数据结构（旧连接测试按本机 IP 判断），底层 Python 依赖采用当前离线镜像。覆盖本地与远端两条记录、历史备份、禁用的定时计划、管理员配置、故障回退和升级成功。该基准不等同于用户内网的原始镜像或真实 Gitea 连接验收。
