# 发布核对排队不执行的调度修复

版本：修复升级包 r3，基于前一补丁片段修复包 r2。生产镜像只调整 Worker 主循环的核对顺序，继续保留空侧坐标修复。前端、执行器和升级器沿用原固定镜像及文件。

## 故障链与验收缺口

用户升级前一修复包后，任务仍为 `publish_unknown`，核对状态为 `queued`，提示“已请求核对，等待工作进程执行”。此时原来的评论片段错误只是尚未被新一轮核对覆盖的历史值，不能据此认定新校验器再次失败。

独立复现确认：原 Worker 先更新心跳，再检查模型执行器是否可用；不可用时直接进入下一轮，跳过后面的 `reconcile_unknown`。因此真实后台进程可以持续显示心跳可用，但核对从未开始，开始时间和结束时间始终为空。

上一轮验收直接调用核对函数，覆盖了评论校验和解除阻塞，却漏测真正主循环的门禁。首次主循环单元测试、测试用例间队列未隔离造成的附加失败，以及真正后台进程的首次故障，均保留原记录。修正测试隔离后，旧交付镜像仍确定失败，未修改阻塞断言来通过验收。

现场的模型运行时状态尚未提供；本次已证明该缺陷可导致用户所述状态，但不能把隔离复现替代现场唯一根因确认。

## 修复与边界

先检查升级维护标记，再执行已有的只读 Gitea 发布核对，最后检查模型执行器并决定是否领取新的审查任务。

- 模型执行器不可用时，已有发布结果仍能核对；核对不使用模型，不续发、不删除远端 Review。
- 升级维护期间仍不执行核对，保留任务状态写入保护。
- 模型执行器不可用时仍不领取新的模型任务，不绕过模型运行时健康门禁。
- 已有发布互斥、数据库领取条件、身份与固定版本校验保持原样。

主循环仍串行执行。若它正在处理其他审查，核对需等待主循环返回；本次没有新增后台线程。工作进程未启动、维护标记未解除、Gitea 无法访问和真实片段不匹配，也不能通过此修复自动消除。

## 固定验收

人工基线是反复点击核对、读取任务接口并人工区分心跳与实际开始时间。目标用户为管理员；支持输入为已有冻结发布结果、可访问的 Gitea 1.26.4、正常启动的单实例 Worker。门槛为维护期间零核对、执行器不可用时零新增模型任务、已有 Review 核对成功、远端 Review 集合不变及后续队列可领取。

- 旧交付镜像：真正启动 Worker 并停用模型执行器后，核对持续排队，开始时间为空，心跳正常；故障与现场状态一致。
- 当前源码七十八项相关回归通过；固定交付镜像四十九项相关回归通过，包含维护、模型不可用和模型就绪三种主循环分支。
- 新交付镜像：真正的 Worker 主循环与官方 Gitea 1.26.4 通过十五条行内评论回读。维护标记存在时核对暂停；移除后，在模型执行器仍不可用的条件下完成核对、清除阻塞；没有新增模型任务，远端 Review 集合保持不变，后续任务可领取。
- 补丁片段校验、分页、历史去重、版本保护继续通过。前端生产构建与修改文件语法检查通过。
- 从前一 r2 包升级到最终 r3 包的隔离验收通过，耗时四十七点五七五秒，原登录会话恢复。回读升级后真实 Worker 容器中的文件摘要，确认已加载新主循环。
- 最终包导入的固定镜像再次通过真实 Worker 主循环与 Gitea 验收。归档摘要与文件清单逐项通过；版本化归档摘要为 `384796a2cfd2724ce75ed4d1043af10315aae9f1d47d005ccfffed96505152a9`。

现场恢复、其他 Gitea 版本、模型审查准确率和人工精力减少比例尚未验证。
