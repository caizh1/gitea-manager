# 执行器镜像缺文件修复

2026-10-20 确认：此前 `manager-backup-timeout-fix-20261016-r1` 的备份代码修复有效，但其执行器镜像构建遗漏了 `runtime_probe.py`、原生会话依赖模块与结果结构文件。升级预检执行 Python 时找不到探针文件，退出码为 2；错误仅写入标准错误，而升级器只解析标准输出，最终显示“执行器检测输出无效”。这是交付构建缺陷，不能通过跳过预检或增加超时解决。

本次补齐 Docker 构建上下文白名单和镜像文件，并在构建阶段验证模块导入与结果结构加载。升级器在探针输出无效时记录最多 4096 字节标准错误，仍拒绝停止旧 Manager。探针容器没有挂载业务凭据。

新增 `scripts/executor-image-acceptance.py`，同时检查真实运行时探针及执行器默认 Gunicorn 启动后的健康接口。条件与升级预检一致：Linux amd64、禁网、只读文件系统、2 GiB 内存、128 进程限制、临时目录和权限限制。不挂载源码。打包器导出执行器镜像前必须通过该检查。

旧 r1 镜像的缺文件错误已复现；修复镜像探针已通过版本、服务健康及单次创建会话检查。升级控制器回归 12 项通过，前端重新构建通过。完整包的隔离升级结果以交付时附带证据为准，不把隔离机器结果视为用户内网宿主机验收。

保留已通过的备份归档流修复。应使用 r2 替代 r1，在 Manager 部署服务器执行升级；先手动备份成功，再恢复定时任务。
