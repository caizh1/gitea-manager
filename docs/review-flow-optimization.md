# 大 PR 审查流程优化与验收记录

## 验收口径

按用户最新要求，本轮停止千行嵌入式与 QEMU 大 PR 的真实模型测试，改用 200 行固定嵌入式样本，验证端到端十分钟以内完成。重点检查完整执行链路、结构和位置校验以及最终 Review 发布，不逐项核对缺陷内容、不追加修正版对照，也不计算召回率、误报率或人工节省比例。正常结束不代表已经验证缺陷判断质量。

200 行本身不是必须拆分的条件。计划仍按完整函数、必要上下文与完整请求 Token 预算生成；同一主审已经联合覆盖的关系不再另发关联任务。所有支持变更行必须恰好归属一个主审批次，P0/P1 发布前仍需独立反证。非法位置、遗漏候选、未完成输出继续拒绝，不以放行错误结果制造成功。已有任务保留冻结计划；产品任务内部保持串行。

此前千行样本原流程为 8 次主审、28 次关联、36 次反证，共 72 次。16～20 次曾是该样本的优化目标，不是强制截断上限。本轮大 PR 未完成最终验收，不宣称已达到该目标；相关记录保留。
## 实现边界

新流程以固定 base/head 的 Git 对象校验内容建立 C/C++ 语法关系，记录文件、版本、范围与内容摘要。按文件、函数、修改块优先切分，超预算再拆分。按完整函数组合控制每次约 320 条变更行；关联按函数体实际行数控制工作量，小函数可合并，不能统一用函数个数把关联切碎。直接调用、可解析对象状态读写和资源生命周期关系触发跨批检查；共享类型名本身不触发。宏、间接调用、无法唯一解析的符号及未读取的工程文件明确列为分析限制。

嵌套成员按完整路径区分；整个对象的确定性写入会关联其成员使用者。类型名先绑定声明来源；变更接口与其实际使用者形成单独关系。关联装箱以已测输入估计进行提案，每个最终请求都重新完整分词，不拿估计替代校验。单个语法范围及必要保护上下文无法容纳时，保留拆分覆盖记录并阻止正式发布，不把未检查的跨片段依赖当作已验证。

主审和关联全部结束后，程序收集候选并分组反证。每组保留候选来源单元的完整证据与保护条件，不沿关联图再次扩展到未见过的全局上下文。只合并完整字段和证据一致的重复候选，保留所有来源；标题相同不是去重依据。每个 P0/P1 都有独立编号与结论。完整请求按实际 tokenizer 计数；超出已批准调用预算时重新确认，不丢弃任务。

## 优化前基线

合成 PR 旧流程成功发布，但存在大量重复意见：12 个植入位置均被报告，不能把 121 条评论当成 121 个独立缺陷。QEMU 低思考强度基线在第 35 次调用因 JSON 语法错误停止，耗时约 2,512 秒；此前高思考强度基线曾遇到输出长度耗尽。失败记录保留，不能计为成功验收。详细调用、报告和计量将保存在隔离验收目录中。

从执行器保存的 SSE 用量回执读取：合成旧流程输入 1,376,726 Token、输出 742,035 Token，72 个单元尝试合计 4,843.4 秒；QEMU 低思考旧流程输入 677,499 Token、输出 398,573 Token，35 个尝试合计 2,480.2 秒。这里的尝试耗时不含人工等待、整次任务排队和发布修复时间，不能混为端到端耗时。原始记录位于 `work/review-flow-20261027/`，不提交源码或访问凭据。

## 输出协议调整

新建任务使用源码位置协议：一条意见只需位置、级别、标题与自然语言正文，摘要和限制可选。运行时映射固定快照位置，跨范围、歧义、不可评论行和未完整输出仍严格阻断。多处证据通过可选相关位置或反证所见完整上下文核对。详见 `review-structured-protocol.md`。已开始的编号协议任务不切换。

## 预处理传输修复

大请求曾在计数进程的标准输入管道上触发短超时，重试时无法继续写入而等待到预处理超时。现改用自动删除的匿名输入文件，保证计数进程读取完整请求并收到 EOF；仍保留超时、内存预算、租约与取消检查。延迟读取的大请求回归已覆盖此路径，已完成的模型响应可从原记录继续，不重新调用模型。

## 输出额度耗尽的恢复

版本 4 的任务只有在保存回执明确表明 finish_reason=length 时，才把关联任务按原函数关系或反证任务按候选拆分，最多两层。原失败保留，截断输出不被采用，原关系和候选不能遗漏；扩大的调用预算通过新的可见计划确认。未知回执和普通格式错误不使用此流程，历史版本任务也不自动改计划。
