# AI 审查用量帧与自动压缩修复

版本：manager-review-usage-20261014-r1。

## 原因与修改

工具调用响应结束后，上游以 choices 为空数组的独立 SSE 帧返回 usage。网关此前把这种帧当成心跳丢弃，导致原始诊断存在真实 Token 用量，OpenCode 却收不到计数，无法据此触发自动压缩。

现在保留包含 usage 对象的帧及其原始顺序，不将其计入模型正文额度。原有工具白名单、参数完整性、只读路径、任务授权、预算和结果 Schema 校验保持。

## 验证

- 流式回归覆盖逐字节、七字节、完整块输入，usage 位于工具结束标记之前和之后；用量、工具参数和结束标记原样保留，心跳继续过滤。
- 固定 Linux amd64 OpenCode 1.18.7 的真实进程，使用无外网的本地模型协议替身：输入 200000 Token 时不压缩；210000 和现场的 260989 Token 时必须出现压缩开始、压缩完成、恢复审查和结构化结果持久化。
- 同一测试在原 r2 镜像中准确复现两项压缩缺失；修复镜像三个场景全部通过。协议替身报告的用量用于控制阈值，不代表真实模型生成或缺陷识别质量。
- 五项网关和压缩专项测试通过，前端重新构建通过，四十个构建文件与复用的已发布前端镜像内容一致。

真实二进制回归入口：deployment/test_compaction_usage_binary.py。其测试结果读取持久化结果文件，不依赖终态已释放的内存字段。

## 交付边界

基于 review-parameters-20261014-r2 已发布 Linux amd64 镜像，仅替换执行器的 native_gateway.py；后端和前端镜像原样复用，保留此前升级维护窗口、会话历史核对和模型参数修复。交付通过 upgrade.sh 完成离线升级。

本补丁解决用量帧丢失，不宣称解决模型重复检索、所有上游错误或任意任务必定产出结论。内网实际模型、原失败 PR 的结果、耗时和人工介入比例仍由部署复验确认；不宣称达到减少人工 80% 的目标。
