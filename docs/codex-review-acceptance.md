# Codex Code Review 接入与验收记录

## 实现范围

Manager 保留模型地址、密钥、模型选择和预算配置入口。新安装默认选择 Codex，模型默认值为 `DeepSeek- V4.1-Flash`。已配置模型和历史任务沿用原协议，OpenCode 可显式选择。

执行器固定 Linux amd64 Codex CLI 0.169.0，使用原生命令 `codex exec review`。Manager 提供冻结的完整 diff 和只读源码 MCP 工具。Codex 主审、每项 P0/P1 的独立反证、历史问题复核使用独立原生会话。历史复核接受原生审查封装或完整历史 JSON，均进行确定性证据校验。

Git 缓存按实例、仓库稳定 ID、授权范围隔离。首次获取完整历史，后续 fetch 增量对象，相同提交复用。快照由 Git 对象提取，忽略 export-ignore，记录链接、子模块和 LFS 指针且不跟随外部目标。任务快照独立，缓存获取和清理使用跨进程互斥。网络和本地准备分别计时。

自动分析仅写 Manager。新增意见、状态变更及固定版本总览由用户预览后确认，确认绑定版本和结果摘要。未选项继续留在 Manager。写入前复核权限与版本，未知回执只读核对。源码工具不暴露 Shell、文件修改和任意联网。

## 已验证范围

- 官方 DeepSeek 公网 Responses 接口完成 Linux Codex 原生 review、多轮只读工具调用、流式终态和用量回传。公网模型使用官方目录中的 `deepseek-flash`，仅用于隔离验收。
- Python 审查回归 707 项测试、379 个子检查通过。另行执行权限、迁移及发布边界检查。
- 2001 单元历史大规模回归通过，耗时约 249 秒。
- Git 对象提取验证 export-ignore 和链接隔离，本地缓存首次获取、复用、增量更新、清理通过。
- 无头浏览器验证默认模型展示和窄屏布局，使用固定隔离 API 数据。
- 执行器交付镜像的固定版本检查、无网络启动和健康接口通过。

## 真实 Gitea 三轮记录

隔离 Gitea 1.26.4 已完成初审发布、开发者修复、复审发布与问题复发三轮。首次新增 1 个 Review。第二轮修复原问题，并发现独立的非数值输入兼容性问题，累计 2 个 Review。第三轮累计仍为 2 个 Review，没有重复发布。第三轮存在两个候选关联冲突，状态保守保留“待确认”，该样本证明了工程链路与去重，同时记录了模型判断不足。

上述修复只处理数值零，还未恢复所有假值输入行为，因此补充以等价完整保护方式进行复验。实际结果写入最终交付记录。

## 验收限制

内网 New API 不可从本机访问，准确模型 ID `DeepSeek- V4.1-Flash` 的内网协议兼容与质量尚未实测。Manager 在启用或切换 Codex 模型链路时执行 Responses 工具往返检查；该检查仍需结合实际原生审查验收。

尚未冻结用户项目的 20 个代表性 PR、100 次版本变化及独立人工基线。准确率 95%、P0/P1 召回率 90%、人工维护精力减少 80% 均未验证。小型合成仓库、接口回归和安装包检查不能替代这些指标。

公网验证曾出现 Markdown JSON 围栏、历史结果封装差异、检索参数错误和候选编号遵循差异。完整 JSON 围栏与完整历史 JSON 已适配，逐候选独立反证避免依赖编号复述。超预算、缺失证据、截断、异常终态仍按未完成处理，不发布 PASS。原始失败证据保存在本地隔离验收目录。

资源消耗尚无与 OpenCode 的同条件对照，不能认定 Codex 更轻量。后端、迁移 Worker 与执行器采用多阶段构建，运行层不保存离线 wheels。离线包同时保留 OpenCode 回退二进制。
