# 本地独立环境

本机入口：Gitea `http://127.0.0.1:3000`，Manager `http://127.0.0.1:5480`，Git SSH `127.0.0.1:2222`。后端 5000 端口仅存在于容器网络，不占用宿主机端口。

## 启动与停止

需要 Docker Desktop/Engine、Compose、Python 3，以及构建前端使用的 Node.js/npm。部署包已经包含前端构建结果和后端离线依赖；首次启动脚本如需重建前端，应先在项目根目录运行 `npm --prefix frontend ci`。若直接使用包内构建结果，可先运行 `python3 scripts/local-env.py status` 生成凭据，然后按下面 Compose 命令启动并初始化。

首次准备公共镜像（已有镜像可跳过；离线环境需事先导入对应镜像）：

```bash
docker pull --platform linux/amd64 gitea/gitea:1.26.4
docker pull --platform linux/amd64 postgres:17.11-bookworm
docker pull --platform linux/amd64 python:3.11-slim
docker pull --platform linux/amd64 nginx:1.31.1
```

常规开发启动：

```bash
python3 scripts/local-env.py start
python3 scripts/local-env.py status
python3 scripts/local-env.py stop
```

离线部署包带有 `offline/运行镜像.tar` 时，先导入其中的 Linux amd64 镜像，再使用已有前端产物和离线 wheels 构建，无需访问 npm 或 pip 源：

```bash
docker load -i offline/运行镜像.tar
```

使用部署包已有前端产物：

```bash
python3 scripts/local-env.py status
docker compose --env-file work/本地环境/.env -f compose.local.yml up -d --build
python3 scripts/local-env.py init
```

脚本会生成独立随机凭据、初始化 Gitea 管理员 `policy-admin`、创建 Manager 服务器连接并设置本机 IP。账号说明保存在权限为 600 的 `work/本地环境/本地访问说明.txt`；Token 仅保存在受限 `.env` 和 Manager 连接配置中。不要把这些文件加入源码或部署包。初始化与停止不会删除数据。

本地固定容器名前缀 `gitea-policy-`，内网原部署仍使用 `docker-compose.yml` 和 `deploy.sh`，两者配置分开。当前本地镜像采用 Linux amd64，Apple Silicon 通过 Docker 模拟执行；该兼容环境的性能不能代表生产 Linux 性能。

## 数据位置与升级

- Gitea：`work/本地环境/gitea`；PostgreSQL：`work/本地环境/postgres`。
- Manager：Docker 命名卷 `gitea-policy-local_manager-data`，包含 SQLite 数据库、任务锁及 Manager 备份目录。
- Docker Desktop 宿主机共享目录曾实测无法可靠排斥两个进程的 `flock`，因此 Manager 必须使用上述原生卷。启动会执行独立进程锁自检，失败则停止启动，不能通过改成单 worker 掩盖。
- 更新源码后重新构建前端并执行 Compose `up -d --build`。更新会中断尚在执行的进程；先等待批次结束。确有中断时重新预览，不重放原写请求。
- 数据库启动迁移有进程互斥，已验证空库双 worker 启动。生产升级前仍需保留现有 SQLite 备份。本期增加组织归属、身份及权限快照字段，不删除原业务数据；旧模板首次应用前须在页面选择组织并核验名单。

## 运行验证

```bash
# 创建隔离组织、账号和至少 30 个批量样本仓库
python3 scripts/policy-real-fixtures.py

# 在页面选择实例和 policy-qa 组织，导入 template-source，命名“研发保护标准”，
# 对 batch-01～batch-30 完成预览和应用后执行：
python3 scripts/policy-real-acceptance.py
python3 scripts/policy-real-boundaries.py

# 当前组织模板的真实 Git、双人审批、CI、仓库转移、权限变化和失败隔离
python3 scripts/policy-organization-acceptance.py

# 容器依赖齐备后，离线执行全部后端回归
docker run --rm --platform linux/amd64 --network none \
  -v "$PWD:/workspace:ro" -w /workspace/backend \
  -e PYTHONDONTWRITEBYTECODE=1 gitea-policy-local-backend \
  python -W ignore -m unittest discover -s tests -q

npm --prefix frontend run build
```

真实测试脚本仅连接固定本机端口，操作 `policy-qa` 隔离样本，会增加测试 PR、提交和模板。样本账号凭据及 Git 工作目录仅存放在 `work/本地环境`。30 仓库由页面提交，真实行为脚本负责独立核验；1,000 仓库测试使用模拟接口，不能当作真实千仓库压测。
