# PR 评论去重与旧问题状态管理

交付范围：内网测试包。工程行为已通过回归和官方 Gitea 1.26.4 隔离验证；实际部署模型效果由使用者在目标环境验证，不宣称已达到人工精力减少 80%。

## 使用行为

同一 PR 保留固定总览；只有首次出现且可定位的问题发布行内评论。原意见正文、讨论和回复保留，后续只更新受管理状态区域。没有新增问题不再创建正式 Review；报告仍保存在 Manager。

问题有跨版本稳定编号，区分仍存在、已修复、已失效和待确认。总览和任务详情展示依据提交；新提交到达时，旧结论标为上一版本，当前待复核。修复或失效的问题仍参加下次复核，复发沿用原编号及评论。PR 关闭或合并不把问题批量改成已修复。

旧问题复核仅使用首次意见、保存的历史 diff、最新完整累计 diff 和本轮候选。每个问题单独一次请求，没有工具权限，不读取源码仓库、完整文件或调用方；主审查也只读 PR diff。正常请求量为一次主审查加每个旧问题一次复核。模型格式错误、证据引用不符、超时、容量不足或关联冲突均待确认；不循环重试，也不截断证据。

身份不使用标题、行号或文本哈希决定。复核必须逐个说明本轮候选与旧问题是否相同；多个旧问题竞争同一候选或关系不确定时，候选在总览和 Manager 中可见，但不发布重复评论。没有可靠行内位置的确定问题可使用“定位：无”进入台账；无法可靠解析的文字保留原文并提示未跟踪。

## 持久化与恢复

独立台账及 diff 快照保存在 Review 数据库，不随普通任务结果清理丢失。每代每个旧问题只有一份复核记录，发送前持久化 started；重启后已发送但结果未知的请求标为待确认，不重放。主审查终态之后清除主会话总期限，复核分别使用单次模型超时。取消、撤权和换代由现有租约及授权检查终止后续工作。

评论操作先保存待同步记录，沿用 PR 发布锁。创建回执丢失时只按固定标记回读原 Review 及其评论集合，不盲目重发。历史版本状态写入未知时暂停后续修改，直到回读确认，防止旧写入覆盖新结论。评论同步失败单独记录，不覆盖已保存审查结论。

人工编辑或删除机器人评论会留下明确冲突，不自动覆盖或补发。旧评论首次接管时核验机器人、任务标记、固定版本及正文；只有可确定的历史重复才关联，缺少历史 diff 则待确认。

只读接口（沿用现有登录和组织权限）：

- `GET /api/ai-review/repositories/<repository>/pulls/<number>/issues?page=1`
- `GET /api/ai-review/tasks/<job>/issues?page=1`

每页 50 项；任务详情展示复核进度、问题状态、证据提交、diff 引用和评论同步冲突。

## 已验证与边界

- 209 项相关回归通过，随后补充未知写入回读、稳定编号接管、人工修改及删除总览的定向测试。
- 官方 Gitea 1.26.4，真实 Git 连续 15 次版本变化：前 12 次改变行号和报告标题，第 13 次修复，第 14 次撤回，第 15 次复发；始终 1 个稳定问题、1 条行内评论、1 条总览、1 次正式 Review。浏览器确认 Gitea 将旧位置标为 Outdated 时，原评论仍能明确显示当前判断和 SHA。
- 真实 HTTP 模型网关协议验证：请求不携带工具，超过主审查调用额度仍可逐问题复核；这不是实际模型语义质量测试。
- 确定性故障测试涵盖模型失败及非法证据、请求中断不重放、评论创建回执丢失、人工编辑及删除、版本变化、无新增不创建 Review、同一行不同问题、未定位问题后续首次发布。
- 真实 Gitea 的其余矩阵（双进程同时写入、人工回复及同时编辑、force-push 与基线前移等）尚未全部完成；不能用确定性替身测试代替这些目标环境行为。
- Gitea 的评论编辑接口没有比较并交换正文的条件写入能力。回读与 PATCH 之间发生人工编辑仍有竞态，前后核对可以检测部分冲突但不能提供事务级保护。常规“先人工编辑，再自动同步”已保护；严格同时编辑需要服务端支持条件更新。

## 目标环境验收

目标用户为负责同一 PR 多轮审查的维护者。固定输入是历史和当前累计 diff；不支持依赖完整仓库才能判断的结论。用户已决定自行在实际环境测试。

先对代表性 PR 记录人工阅读 diff、核对旧意见、判断状态、查重和维护评论的实际时间，再运行同样的版本序列。至少准备 20 个 PR、100 次版本变化，逐问题人工标注身份和状态。记录请求耗时、Token、待确认比例和人工复核时间，保留失败样本，不以增加待确认比例规避错误。

发布质量目标仍为：修复／失效误判为零、不同问题误合并为零、重复评论减少至少 95%、可由 diff 判断的问题自动处理覆盖至少 90%、人工维护精力减少至少 80%。这些指标尚未验证。

升级使用完整 AI 离线包内的 `upgrade.sh`，保留现有数据库和主密钥。先在目标测试环境验证配置、旧任务历史、首次接管及连续更新，再评估实际部署模型质量。不得把隔离工程验证当作内网模型验收。
