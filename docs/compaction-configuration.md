# AI 审查上下文压缩配置

在 Manager 的“AI Code Review → 模型与设置 → 审查资源预算”中配置：

- 模型上下文窗口：默认 262,144 Token，必须与模型服务实际开放的容量一致。
- 上下文压缩阈值：默认 210,000 Token，即 210K；保存后对新创建的任务生效。
- 阈值加输出预留不能超过模型窗口。输出额度为 0 时，配置校验至少预留 8,192 Token；这不等于确认模型服务的实际输出上限。

既有排队或执行中的任务沿用创建时冻结的配置。旧部署升级后请打开设置并保存，使后续任务使用新的窗口和阈值；历史任务没有该字段时保持原来的窗口行为。

压缩由 OpenCode 在轮次边界根据用量判断，达到阈值后压缩；不是在逐 Token 输出中即时切断。新版 1.18.7 使用输入窗口与零额外预留配置。兼容版 1.1.51 不接收自定义输入窗口，按该版本真实算法换算内部窗口，避免配置失效。设置了显式阈值后，关闭提前删除旧工具输出的自动清理。

任务详情在压缩期间持续显示“模型正在压缩上下文”，执行记录保留开始和完成事件，完成事件带耗时。压缩未完成而任务结束时记录中断，不将执行器心跳当作压缩进展。

已删除 Manager 两处 200 行读取指令，以及网关把 read.limit 强制裁剪为 200 的逻辑。模型提供的 limit、offset 原样交给原生工具；省略 limit 时不再由 Manager 注入。OpenCode 原生工具自身的输出截断、既有整次检索操作额度和任务总期限仍按各自设置执行；只读权限与路径隔离保持有效。

## 本轮验证边界

- 后端相关 90 项回归通过，覆盖配置保存、非法值、任务冻结、事件持久化和既有审核协议。
- 执行器 2 项专项回归通过，覆盖两个版本的阈值边界、压缩状态、读取参数分片和越界读取拒绝。
- 浏览器固定样本验证通过：默认 210,000、保存修改、压缩期间持续提示、压缩完成消失及日志可见；无页面异常。
- 两个真实 OpenCode 二进制配合协议替身，验证 209,999 Token 不压缩、210,000 Token 压缩；随后恢复审查并提交结构化结果。一次 read 请求可读完 500 行样本。
- Token 用量与模型响应由固定测试样本提供，不代表真实内网模型审核质量或速度，也没有据此宣称降低人工成本 80%。内网 262K 模型的实际运行耗时待验收。
