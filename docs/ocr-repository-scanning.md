# 整仓 AI 扫描

在「AI Code Review」下进入「整仓扫描」。选择已接入的 Gitea 实例、仓库和分支。手动扫描先预览范围，再用页面显示的固定提交启动。定时扫描每次读取所选分支的当前提交，按仓库和分支各自记录进度及报告。

平台管理员可沿用 AI Review 模型，或在 OCR 模型配置中保存专用端点和凭据。测试连接实际请求模型发出一次工具调用。令牌在 Manager 加密存放，OCR 仅收到当前执行的代理凭据。工作台、进度和报告显示模型已返回的累计 Token 用量。按需可以手动终止任务，消耗统计会保留。

## 进度和恢复

Manager 使用 Open Code Review v1.14.4。执行器运行原生整仓扫描并启用逐文件批次。已完成文件的计数来自 OCR 会话的成功检查点，包含没有发现的文件。候选和排除范围来自原生预览和固定提交的 Git 文件清单。

短暂的模型限流和服务异常会显示错误、重试次数和下次重试时间。原生单次执行的重试耗尽后，Manager 自动以原提交和原规则使用检查点继续扫描。续扫会关闭 OCR 的二次模型去重，原样保留此前已保存的意见。工作进程重新启动后仍从持久记录接续。若需更换密钥，保留原端点和模型后在任务中选择「继续扫描」。旧版曾因预算暂停且已有检查点的任务也可用此操作接续。

「终止扫描」需要二次确认。系统停止后续调用、清理工作目录、OCR 会话及报告，保留终止审计。已经下载到本地的报告由使用者管理。

## 上下文与覆盖范围

平台管理员可在「整仓扫描 → 模型配置」为「继承 AI Review」和「OCR 专用」分别保存「OCR 输入上限」。默认值为 58,888 Token。DeepSeek V4.1 Flash 1017 的端点确认支持百万上下文时，可设为 1,000,000 Token。OCR 会按输入上限的 80% 估算单文件筛选门槛，正式审查的提示词、仓库规则也占用输入空间。单文件读取上限仍为 2 MiB。

手动任务在创建预览时保存上限，定时计划在每次创建任务时读取所选模型配置。已预览或已开跑的任务沿用保存的值。用新上限重新扫描现有提交时，新建任务并重新预览。

整仓任务持续调度 OCR 选中的文件。每个文件使用独立的审查对话，结果以文件为单位持久化，输入与输出 Token 可跨多个请求累计。单次上下文限制仍取决于模型和 OCR 配置。OCR v1.14.4 会过滤超过其文件大小或提示词阈值的文件，预览与报告会标明排除原因。

项目汇总读取逐文件发现。若模型拒绝汇总请求且所有候选文件均已完成，系统仍导出完整的逐文件报告，进度时间线会记录项目汇总未生成。

## 报告和部署

可下载独立中文 HTML、Markdown、OCR JSON，以及预先选择的原生文本、SARIF 和原生会话 HTML。HTML 可断网打开和筛选，源码定位链接指向 Gitea 的固定版本。报告会保留来源代码片段，按仓库授权查看和下载。

离线安装与升级复用 Review 存储和执行器服务。构建前运行运行时准备程序校验固定二进制 SHA-256。构建后的 Linux amd64 执行器应包含 `/opt/review/ocr` 和许可证。

## 隔离验收

`backend/tests/test_ocr_scan.py` 使用固定官方二进制验证逐文件检查点、多个模型错误和原生格式。

`scripts/ocr-scan-acceptance.py` 用后台浏览器、隔离 Gitea 1.26.4 和 DeepSeek 官网模型验收。用环境变量 `OCR_ACCEPTANCE_DEEPSEEK_KEY` 注入凭据，只使用公开仓库。普通场景验收配置、预览、扫描与离线 HTML。故障场景在已保存进度超过八成时注入两轮 429 和 500，期间重启 Worker，核对故障前检查点、重复主审和最终报告。
