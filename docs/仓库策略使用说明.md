# 仓库策略中心第一期

本期闭环为：选择实例和组织 → 创建或导入组织模板 → 选择本组织仓库 → 预览差异 → 手动批量下发 → 查看逐仓库核验结果。

## 适用对象与边界

- 使用现有共享管理员登录；审计如实记为“共享管理员”，不能追溯到某个自然人。
- 模板绑定一个已配置的 Gitea 实例和一个组织。当前严格适配并验证 Gitea **1.26.4**，其他版本会阻止执行，避免字段兼容问题。本功能不是企业版原生继承，仓库仍可在 Gitea 手工修改。
- Manager 继续使用 SQLite，支持同一 Linux 文件系统上的双 Gunicorn worker。数据库、任务锁必须共享可靠的本地持久目录；Docker Desktop 使用 `compose.local.yml` 的原生数据卷。多节点 Manager、网络文件系统和其他 Manager 数据库未纳入支持范围。
- 每批 1～5,000 个仓库，每模板 1～50 条规则。归档、拉取镜像、无管理权限仓库不可应用。
- 本期没有版本、仓库绑定、自动同步、独立漂移巡检或一键修复。再次预览可比较当前规则，需要重新确认后才能应用。

## 操作步骤

1. 在“服务器管理”保存 Gitea API 地址和具备目标仓库管理权限的 Token。本地初始化脚本已完成这一步。
2. 打开“仓库策略中心”，依次选择实例和组织。组织是搜索选择，不能自由填写。创建空白模板并添加规则，或者“从仓库导入”搜索本组织源仓库、读取规则、勾选需要导入的规则。填写名称后保存。
3. 每条规则按 Gitea 顺序配置：表达式 → 推送 → 强制推送 → 合并请求批准 → 合并请求合并。推送和强推使用三选一，人员、团队紧邻对应限制，以搜索多选填写；CI 检查名称每行一项，文件模式用分号分隔。
4. “另存为”创建同组织独立副本。“复制到其他组织”必须选择目标组织，明确清除原团队并重新选择，点击“核验名单”确认后保存。修改、删除模板均不会自动修改仓库；提交过的批次保留原始模板、组织、身份和来源快照。
5. 选择模板进入“批量应用”，仅列出所属组织仓库。支持搜索、跨页勾选和“选择全部当前结果”。“清空”撤销当前选择；切换组织或实例清空选择。当前结果冻结为本次仓库清单，以后新增仓库不会自动纳入。
6. 点击“预览差异”。展开仓库行，查看新增/更新规则、字段前后值、保留规则、优先级与当前匹配分支。可以链接到该仓库的 Gitea 原生分支设置查看仓库辅助信息。没有当前匹配分支的规则也可能约束未来分支。
7. 点击“应用 N 个可执行仓库”。阻塞仓库不会进入写入。处理失败不会阻止其他仓库；页面每两秒刷新持久化进度。
8. “执行记录”查看历史批次、结果筛选、模板快照、每条操作及回读内容。“已核验成功”表示有效保护字段经完整回读符合预期，不能等同于已逐一执行所有业务行为测试。

## 与 Gitea 对齐的配置表单

模板采用完整编辑页面，保留 Manager 外层导航。单条规则使用 [Gitea 1.26.4 原生表单](https://github.com/go-gitea/gitea/blob/v1.26.4/templates/repo/settings/protected_branch.tmpl)的中文名称、原文说明、顺序、缩进、单选/复选控件及禁用联动，不用近义改写替代。人员与团队采用 Element Plus 搜索多选。桌面规则导航在左侧，窄屏改为上方；优先级在规则列表单独管理，保留导入数值和顺序。Gitea 原生中文文本的许可证见 `docs/licenses/Gitea-MIT.txt`。

- **表达式**：填写分支、受保护文件、不受保护文件。组织与来源位于模板信息区域，规则内部无需填写组织。
- **推送**：禁用、启用、受白名单限制三选一，下方配置用户、团队、部署密钥及签名要求。
- **强制推送**：禁用、启用、白名单三选一，与普通推送选项独立，遵循原生网页及 PATCH 语义。
- **合并请求批准**：批准人数、批准白名单、过时批准处理、状态检查及检查名称。启用“取消过时的批准”时，“忽略过期批准”禁用。
- **合并请求合并**：启用合并或合并白名单，下方设置拒绝审查、正式审查请求、落后分支、管理员限制。

用户下拉框默认列出组织成员，输入关键词后可搜索同实例其他账户，支持外部协作者。组织成员不等于有每个仓库的权限，Manager 不创建账户、不添加协作者、不扩大团队权限。团队显示“组织 / 团队”，每页 20 项，列表底部加载下一页。团队成员由 Gitea 管理，Manager 保存团队引用，不复制固定成员表。

已保存或导入的名称不依赖当前候选页，搜索失败时仍保留。错误信息和“重试查询”位于候选列表底部。候选可见只说明可以选择，实际目标仓库权限仍在批量预览核验。搜索使用 500 毫秒防抖，忽略旧条件的迟到响应，并计入现有每实例每秒两次配额。

本次迁移增加模板组织、稳定身份和来源信息，批次增加组织快照，仓库明细增加权限快照；原名称数组和 `team_org` 仍兼容 Gitea API。旧模板及历史不重写，显示“尚未归属组织”，需在编辑页选择组织并核验名单后才能下发。旧的未提交预览需要重建，已提交历史仍可查看。

用户与团队保存实例 ID 和实际身份 ID。删除后同名重建会被阻塞，需移除旧选择、重新选择并核验新身份；改名后点击“核验名单”确认新名称，原 ID 保留。组织改变时原团队不按同名映射。含多个组织团队的旧模板须分别整理，不能整体自动转换。来源仓库只提供导入快照，源仓库删除或权限变化不影响已保存模板。

新一期验收和边界见 [组织模板验收报告](组织模板验收报告.md)。此前表单对齐报告保留为历史证据，不代表当前行为。

## 规则语义

- 支持接口的 30 个保护字段：名称、优先级、审批数、16 个开关、9 个名单/CI 数组、2 个文件模式字段；时间、内部 ID 不复制。
- 只创建或更新**同名**规则。`main` 不会改成 `master`，未纳入模板的规则保留。
- 模板内部规则可以重叠，但重叠时必须明确不同优先级，数字小者优先。模板规则与保留规则发生匹配范围重叠时，本期采取保守阻断，需要管理员先明确调整范围；不会静默改变其他规则优先级。
- 支持常用 `*`、`**`、`?`、字符组、范围、反向字符组、花括号选择和标点转义。普通分支名按 Gitea 进行大小写折叠；通配模式区分大小写。为保证匹配分析一致，不接受 `\d` 等字母数字反斜线转义，需改成 `[0-9]` 等明确字符组。超长、非法或无法分析的规则会被阻断。
- 禁用开关的依赖名单、不再生效的旧审批选项按有效策略归一化；不会把停用字段的残留值误判为有效限制。普通推送关闭不裁剪独立强推许可。显式 `false`、`0`、空数组和空文本会正确写入。
- 启用允许名单且名单为空，表示没有名单成员获准。启用 CI 且上下文为空，沿用 Gitea 对已上报检查的处理；要要求特定流水线出现，必须填入检查名称。审批数为零不要求审批。
- 审批人员要求 PR 读取权限；直接 Push、强推和合并人员要求代码写入权限。组织团队使用分单元权限判断。停用账号会被阻断。跨组织团队不按同名映射，必须另存模板并明确修改组织与团队。
- 文件例外可能允许绕过直接 Push 禁令。签名、CI、合并与文件策略最终由 Gitea 执行；Manager 负责配置及核验。

接口字段依据：[Gitea 1.26.4 保护规则结构](https://github.com/go-gitea/gitea/blob/v1.26.4/modules/structs/repo_branch.go)、[权限与分支匹配实现](https://github.com/go-gitea/gitea/blob/v1.26.4/models/git/protected_branch.go)、[通配表达式实现](https://github.com/go-gitea/gitea/blob/v1.26.4/modules/glob/glob.go)。

## 并发、失败与恢复

同实例批次串行，每批最多两个仓库并发。所有策略接口请求（包括搜索、导入、预览、执行）通过同一数据库分配间隔 500 毫秒的请求时隙；双 worker 共享配额。批量查询、人员和团队预检也消耗配额，几百仓库可能需要较长时间。

预览保存模板、组织、身份、实例连接、仓库有效规则和名单权限快照。提交时模板或连接变化会返回冲突；执行前仓库名称、所属组织、默认分支、权限或规则变化会阻断该仓库。每次写入前再次复查规则及仓库身份，写后完整回读，最终复查名单权限。Gitea API 没有跨多个规则的事务或条件写入，仍存在外部管理员恰好在最后复查与写入之间修改同一规则的窗口；维护期间应避免同时手工调整。

Gitea 1.26.4 的 POST 会在普通推送关闭时裁剪强推配置，原生网页和 PATCH 则支持独立设置。Manager 创建该组合时先读取并严格核对预计的中间状态，再 PATCH 补全，随后再次核验。任一步骤超时或中断都不会盲目继续或重放；新预览是恢复入口。

超时、响应丢失不盲目重复写入，而是回读判断。全部符合预期才成功；发生部分变更会明确标为“部分已修改”，无法回读则“结果待确认”。进程退出后的运行中批次标为中断，不自动重放。恢复操作必须重新预览，以实际状态为准；已经成功的仓库会显示无变化。

新增写接口要求登录、同站点来源及 `X-Policy-CSRF`，先读取 `GET /api/repository-policies/csrf`。凭据不进入策略审计或错误正文。历史保存在 Manager 数据库中，模板删除不删除历史；备份 Manager 时必须同时备份该数据库。

## 主要接口

统一前缀 `/api/repository-policies`，使用现有登录会话。

| 路径 | 功能 |
|---|---|
| `GET /servers`、`GET /schema`、`GET /csrf` | 无凭据实例列表、字段定义、安全令牌 |
| `GET /organizations?server_id=…&q=…&page=…` | 组织搜索选择，返回稳定 ID，每页 20 项 |
| `GET /repositories?server_id=…&org=…&org_id=…&q=…&page=…&limit=…` | 组织仓库搜索分页，单页最多 100 |
| `GET /repositories/{id}/rules?server_id=…&org=…&org_id=…` | 读取规则及稳定身份，不建立源仓库依赖 |
| `GET /users?server_id=…&org=…&org_id=…&q=…&page=…` | 空关键词默认组织成员，输入关键词搜索实例账户，每页 20 项 |
| `GET /teams?server_id=…&org=…&org_id=…&q=…&page=…` | 组织内团队搜索，返回组织及稳定团队 ID，每页 20 项 |
| `POST /identities/verify` | 明确核验旧模板及改名身份，返回更新的规则和身份供确认 |
| `GET/POST /templates`、`PUT/DELETE /templates/{id}` | 查询可用 `org_id` 或 `legacy=1`；保存需组织及稳定身份，编辑需当前 `content_hash` |
| `POST /batches` | 冻结预览，参数 `template_id`、`content_hash`、`repo_ids` |
| `POST /batches/{id}/apply` | 提交已预览批次；重复提交返回同一批次 |
| `GET /batches`、`GET /batches/{id}` | 历史、进度、仓库结果，详情支持 `page` 和 `status` |

## 验收标准

人工基线为逐仓库进入 Gitea 原生设置并配置相同有效保护字段。固定样本要求支持字段的差异与最终状态全部正确，误报成功为零，未管理规则意外修改为零；每仓库失败独立，跨进程去重与请求时隙一致。操作减少目标为 80%，交互次数、自动化运行耗时与真人工时分开报告，不将模拟规模当作真实规模。

执行记录与验收结果参见交付的中文测试报告。后续范围参见 [仓库策略待办清单](仓库策略待办清单.md)。
