# 备份长事务导致 Manager 登录失败的修复

## 现场事实

2026-10-20 用户的独立内网 Manager 在备份期间，后台授权与登录请求均出现 `sqlite3.OperationalError: database is locked`。授权请求阻塞在 `policy_request_slots` 的更新，登录阻塞在 `access_login_throttle` 的写入。这是 Manager SQLite 写入竞争，不是密码错误，也不是源 Gitea 的 PostgreSQL 报错。现场持锁进程尚未单独回读，不能将错误 SQL 当作持锁者证据。

## 可复现的代码缺陷与修复

备份传输后给 ORM 记录赋值 `file_path`，密钥快照又赋值 `file_size`。读取已过期的服务器 ORM 配置会触发自动刷写，将待提交改动写入 SQLite。此后制品传输与 ZIP 清单哈希持续运行，写事务却一直留在会话中，其他连接无法写登录限流和共享请求时隙记录。

独立文件数据库双连接实测：耗时处理期间另一连接报同样的锁错误；原会话提交后立即可写。回退本次两个提交点，固定回归在普通配置和外置密钥两种情况下均能复现锁竞争。修复为在设置文件路径后、密钥快照更新后分别提交短事务；备份仍保持运行状态，最终成功仍由原完整性门禁决定。

没有关闭登录限流、共享请求时隙或完整性校验，没有增加 SQLite 等待时间，也没有删除数据库或日志文件。

## 验证

- 新回归使用真实 SQLite 文件、独立连接和独立请求线程，在两个耗时边界验证登录写入、真实登录接口及会话读取成功。
- 备份单元回归 26 项：25 项通过，1 项因为后端镜像未安装 Git 命令而跳过。
- 认证回归 22 项、升级控制器回归 12 项、中断任务收尾回归 1 项通过。
- 真实独立增强版 Gitea、PostgreSQL、SSH 网关：本地一次、连续 SSH 两次备份及制品传输中断注入通过；备份正文摘要、源服务运行及实例锁清理均核对。每次在密钥、制品处理边界均以独立连接成功写入登录限流与共享请求时隙记录。
- 原始失败是测试源码只读挂载下诊断目录不可写；配置独立可写临时诊断目录后重新执行，未修改断言。
- 保留前序归档流关闭、异常清理及执行器完整镜像修复；真实容器和最终包升级的结果见交付验收摘要。

## 恢复与边界

若需先恢复登录，应先确认主 Gitea 正常运行、没有正在进行的恢复或升级作业，再重启 Manager API，释放其连接与事务。该操作会中断尚未完成的备份；其结果不能作为可信恢复点。不要删除数据库、WAL 或回滚日志。

重启后可能遗留运行中记录而阻止升级。交付附带 `finish-interrupted-backup.py`，必须指定任务编号；只有 PID 1 启动时间晚于原诊断开始时间，能够证明原 API 中的线程已经退出，才允许将该任务及其步骤标为失败。没有诊断证据、原进程尚在或数据库不存在时拒绝修改。它不停止远端容器、不删除文件、不将失败任务伪装为成功，也不自动删除远端实例锁。

本次修复不增加一小时独立看门狗，不改变当前停写一致性备份策略，也不把用户中途重启主 Gitea 的备份认定为经过一致性验证。用户内网现场仍需安装后回验。
