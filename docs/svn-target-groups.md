# SVN 迁移目标群组与入口发现

## 使用方式

在来源页勾选项目并创建计划后，进入独立的“选择迁移目标”页面。先选择已登记的 Gitea 增强版实例，再选择目标群组。可选择已有根群组或子群组，也可以明确新建一个私有群组。

右侧显示每个仓库的完整目标路径，例如 `firmware/storage/emmc_production`。路径检查会阻止已有目标和计划内同名冲突。点击“保存计划并预检”只启动预检，执行迁移仍需后续的完整读取和停写确认。

连接来源、自动发现、项目选择、计划、预检和执行页面共用圆形节点与连线式步骤条；窄屏自动换行，图标留在正常文档流内。

## 权限和历史兼容

新页面明确提交目标群组 ID，不从随机来源标识生成目标路径。群组列表与选择均读取真实增强版 API 的权限，不接受客户端伪造的群组路径。

选择已有群组表示迁入仓库沿用该群组现有成员和共享权限。Manager 不修改原群组的成员或共享。新仓库保持私有，并关闭导入代码中的自动执行功能。预检保存群组身份及有效授权摘要，执行前、建库及回读阶段再次核对；群组移动、归档或授权变化时要求重新预检。

旧客户端未提交目标群组以及历史执行快照继续沿用原来的独立私有群组规则。新页面编辑旧计划时需要明确选择目标群组。历史记录不被批量改写，已经完成的仓库不自动搬迁。

新建群组是一次明确的外部写入。回执丢失时不会自动重试或按同名接管，请刷新目标列表核对后选择实际群组。

## SVN 入口识别

`/svn` 只是默认候选，不能作为固定规则。填写服务器根地址时，系统会同时尝试默认入口，并在同一来源范围内读取首页提供的子级列表导航；不会因为首页出现一个普通链接就放弃后续列表。自定义 `/repos` 等可从导航中发现。若服务既不公开入口链接，也没有使用默认前缀，需要补充实际的项目列表入口。

识别到的列表入口会显示在发现窗口中。项目 URL 仍逐个通过 SVN 协议验证，不能把普通网页或样式资源当作项目。导航最多读取 32 个列表入口、向下两级，沿用五分钟任务上限。跨来源地址与重定向仍被拒绝。

## 验收范围

人工基线是先记录全部项目 URL、选择或创建目标群组、逐个核对目标路径，再处理迁移后的随机命名。新流程的目标是一次选择群组、一次检查目标路径，避免事后重新组织仓库。

固定验收样本包括真实 HTTP SVN 的根页导航、默认前缀、自定义前缀、无前缀、列表关闭和鉴权失败，以及真实增强版 Gitea 的已有成员子群组迁移、路径冲突和预检后权限变化阻断。界面另行验证普通 HTTP、桌面和窄屏。隔离样本不等于公司 VisualSVN 实机验收；减少人工百分之八十仍未做真实对照测量。
