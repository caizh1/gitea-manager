# 迁移完整性与合并条件补齐说明

本轮面向平台迁移管理员，将 GitLab CE 与开源 Gitea 的固定项目及其依赖迁入当前增强版独立快照。Manager 分支为 `codex/gitlab-gitea-migration`，接收端协议为第三版；源码提交、镜像及二进制摘要见 `offline/git-migration-receiver.json`。

## 输入、边界与质量门槛

人工基线包括逐仓下载 Git、LFS、Wiki、协作资料、制品和 CI 文件，重建关联及规则，再逐项比对。输入必须包含可完整读取的来源身份、目标管理员、已有目标群组、已有账号的明确映射，以及覆盖依赖项目的停写确认。迁移程序不创建业务账号；验收脚本创建的账号仅属于独立测试夹具。

质量门槛为：独立来源对象、文件和规则清单逐项覆盖，必需字段和文件摘要差异为零，未知写入保持隔离，允许与拒绝行为均有实际证据。固定基准覆盖二十七个项目、二十三个实际合并变体，以及每个来源的六类制品协议。范围是固定清单及其闭包，不是来源实例全部项目或所有版本。人工介入比例及节省百分之八十尚无真实公司项目的人工对照计时，保持未验证。

## 两个 P1 的修复

评论附件漏迁：普通评论和行内评论均单独读取附件，按稳定来源编号传输并改写目标链接。两个同名附件分别保留。来源详情和逐议题评论提供独立于全仓评论列表的检查入口；转换遗漏任何对象或文件时不能成功交接。

凭据失效后无法恢复：来源凭据更新独立于业务配置编辑，必须在停止检查点验证原管理员及原来源版本，保留来源配置版本、任务号和检查点。目标令牌也必须属于固定管理员。目标群组授权发生变化时仍允许恢复同一管理员的令牌；原授权快照不变，继续迁移仍被阻断，但可以安全终止，不能要求重新启用已移除成员才能退出。无法继续时可终止任务：接收端永久关闭该任务会话，目标仓库归档保留，回读确认后才释放实例互斥。终止不删除仓库、数据卷或恢复现场。旧凭据失效、同任务恢复和有真实写入的终止均有隔离实例验证。

## 独立来源清单与人员

独立采集器直接重新读取来源，既不调用转换器或盘点器，也不读取迁移检查点作为预期。它重新读取并核对项目路径、名称、说明、归档、可见性、默认分支、归属和链接，再比较稳定对象编号、文件编号、归属、名称、大小、来源可提供的摘要及规则身份。发现后基础属性改变时必须重新发现和盘点，不能把旧说明或归档状态静默迁入。代码、可见引用、LFS 和 Wiki 历史继续使用独立的重新克隆与内容核验。来源清单在写入前、写入后重新比较；Wiki 待办不能跳过清单核验。

负责人和当前评审请求映射到已有目标账号，单个来源人员只能指定一个账号；团队或规则角色可显式展开为多个账号。历史作者仍保留来源身份，历史批准不计入当前审批。交接时按实际目标单元权限核对负责人、评审人和可信 CI 账号，不能把增强版成员的总体 `permission=none` 当作没有单元权限。

## 流水线与复杂合并条件

通过项目流水线、项目作业及触发作业三路闭包枚举子流水线，兼容 GitLab 16.1 的接口。三级子流水线及跨项目触发均保留父级流水线、下游流水线和目标仓库稳定编号。全部可读作业日志、归档、原始报告和元数据均进入独立文件清单；过期或已擦除内容形成明确缺口。目标工作流保持关闭，CI 历史在迁移历史入口读取。

GitLab 的三种合并方法与四种压缩策略转换为允许方式、默认方式和最终门禁。普通合并及半线性合并采用压缩时仍保留独立的双父节点合并提交；快进模式的压缩保留单父节点。半线性及快进模式要求来源分支包含当前目标提交，实际测试先推进目标分支，确认拒绝，再变基并合并。来源语义依据 [GitLab 合并方法说明](https://docs.gitlab.com/user/project/merge_requests/methods/)。

强制流水线成功只接受明确映射的可信 CI 账号对当前 PR 源提交发送的状态；历史成功、普通写入者伪造状态、旧提交成功、新一轮等待或失败均不能解除门禁。CI 接入方使用该账号调用目标原生 `POST /api/v1/repos/{owner}/{repo}/statuses/{sha}`，状态上下文为 `migration/gitlab-pipeline`；跳过状态使用其 `/skipped` 上下文，仅在来源明确允许跳过时认可。需要解决的历史讨论即使位置已过期也继续阻断，直至实际解决。上述约束在最终授权阶段重新检查。

来源的重叠分支规则、Nobody、强推、标签创建及删除语义继续通过实际 Git 和原生 API 验证；不把连接故障或内部错误当作规则拒绝通过。API 和网页会将迁入条件不满足作为可处理的业务拒绝。

## 最终包验收与证据

候选阶段已完成两个来源的二十七个项目交接、逐文件消费、历史 LFS、人员及附件核对，以及五个 Gitea 和十八个 GitLab 合并变体。候选阶段发现并保留的失败包括：测试改密码误改登录名、Wiki 待办跳过清单、制品发布合法推进会话版本、压缩合并命令输出处理、线性条件拒绝被返回为内部错误、项目基础属性未独立复读，验收脚本未建立网页登录会话，以及原生异步检查临时拒绝被当作最终失败。修复后继续使用原任务核对，但续验不能替代最终包的一次完整运行。

最终包入口为 `scripts/git-migration-final-acceptance.py`。它先核对归档全部文件与镜像清单，装载包内镜像，比较三类管理镜像全部 Python 文件和前端静态文件，再启动空白接收端和两套空白 Manager；不挂载开发源码，不复用候选迁移。两类来源均完整执行发现、盘点、传输、交接、消费、规则及后台浏览器验收，Gitea 另执行来源密码和目标令牌真实失效恢复、真实写入后的终止与实例互斥释放，并验证成员已移除且令牌已失效的组合故障。已知 C 产物在包内 Python 基础镜像的无网络容器中执行。

本机最终回执为 `work/git-migration/final-package-20261026-r4/final-acceptance.json`，包含最终包 SHA-256、镜像身份、逐步骤退出码与耗时、全部来源分母和实际结果。最终包必须以该回执的“结果：通过”为通过依据，禁止汇总候选续验冒充最终包通过。凭据及原始失败日志保留在本机 `work/`，不进入离线包。

回归包含七十六项 Python 迁移测试、统一接口权限矩阵和十四项原生接收端／合并条件测试。前端构建已通过；大块体积提示属于既存优化项。

## 未验证与排除

GitLab EE 付费审批、Code Owners 和企业复杂继承继续保持未验证；未支持资料仍会阻断交接。OCI／容器镜像按约定排除。其他源端版本、其他制品协议、旧盘点结构的在途升级、真实大型公司项目、物理宿主机、生产规模和人工节省指标未验证。旧盘点不能直接当作新清单，应先核对兼容性，必要时安全终止并重新盘点。
