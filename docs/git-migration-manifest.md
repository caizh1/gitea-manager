# 协议七：封存清单与恢复

首次封存前，Manager 保存对象和附件的预期清单摘要及封存意图。接收端在同一事务内逐项核对对象、附件关联和摘要，并将不可变清单版本、摘要与封存状态同时保存。最终准备和发布继续核对原清单，再绑定最终归属、代码引用、规则及制品关联；删除回执不能变成新的基线。

恢复通过原“继续”入口。执行器先读取原会话和批次状态：装载状态继续幂等导入；封存或交接状态先检查原清单和全部回执，再继续尚未完成的交接。已封存会话不重新导入对象、附件或代码。身份、清单或预期基线缺失时保留现场并阻断。

接收能力为协议七和 `receipt_manifest=true`。封存请求增加 `manifest`，含版本、对象数、附件数和摘要。新增 `GET /api/v1/governance/migration-sessions/{key}/manifest` 只读核验接口，返回实际摘要、数量及修订号；只允许原会话管理员读取绑定的隔离仓库。会话表增加封存清单版本和摘要，使用原有幂等模型扩展。

清单使用八字节大端长度前缀与 UTF-8 原文，按回执数字 ID 排序，整数使用十进制字符串。对象绑定回执编号、类型、来源编号、目标编号、载荷摘要。附件绑定回执编号、来源编号、父类型与编号、元数据摘要、大小、内容摘要、UUID、附件编号。摘要不包含执行时间、修订号或交接过程中才建立的制品编号；最终发布指纹另外绑定制品编号。

本阶段尚无正式使用者，不自动升级旧批次凭证。既有测试现场保留，协议七验收创建新批次。数据完整性、恢复行为和已确认的平台差异分别记录；不将有限样本的通过率解释为生产环境百分之九十九可靠性。

PostgreSQL 连续导入多批对象使用迁移接收端的原子编号同步，避免在已有最大编号未增加时重复插入索引。该同步不会降低已分配编号；重复批次仍核验原回执。
