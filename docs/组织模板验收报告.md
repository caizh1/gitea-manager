# 组织模板与批量下发验收报告

验收日期：2026-09-12。目标环境为本机独立 Gitea 1.26.4、PostgreSQL、Manager 双 Gunicorn worker、Linux 原生 SQLite 卷；macOS Docker Desktop 以 Linux amd64 运行。不是生产环境或企业付费版验收。

## 实现范围

完成“实例 → 组织 → 独立模板 → 本组织仓库选择 → 冻结预览 → 手动批量下发 → 逐仓库执行记录”。组织只选一次；完整规则页不再填写团队组织。支持空白创建、源仓库多规则导入、编辑、同组织另存为、明确跨组织复制、旧模板归属。源仓库只保留来源快照。

组织、用户和团队使用真实稳定 ID；API 名称仍兼容现有字段。账户和团队同名重建不能静默替换；改名需明确核验确认。组织成员与仓库权限分别处理，Manager 不创建账户、不自动授权。批量执行复用持久化任务、同实例串行、双仓库并发、SQL 共享请求时隙、失败隔离、写后回读与审计。

本期不提供原生继承、强制治理、多用户隔离、自动纳管、持续同步、漂移检查/修复或模板版本。这些能力及依赖、验收条件列在《仓库策略待办清单》。当前内容哈希是并发校验，不是策略版本。

## 固定样本与质量门槛

目标用户：现有共享管理员。输入：已配置实例、可见组织、实际用户/团队，以及具有管理权限的本组织目标仓库。支持上限为单模板 50 条规则、单批 5,000 个仓库；严格适配 1.26.4，归档、镜像和无管理权限仓库不支持。

样本包括 policy-qa 与 policy-qa-other 两组织、同名开发/审查团队、组织内外账户、读写权限不同仓库。批量主样本为 org-center-01～30，每库保留 archive/**，模板含 main 和 release/** 两条规则，其中 release/** 同时设置禁用普通推送与独立强推白名单。另设独立 Git、PR、身份重建和时序探针仓库。

验收门槛：固定样本中全部支持字段正确；误报成功为零；未管理规则意外修改为零；阻塞场景有明确原因；单仓库失败不影响正常仓库。1,000 仓库模拟与 30 仓库真实验收分开报告。人工操作减少 80% 为业务目标，本次未做真人对照实验，不宣称达成比例。

## 首次失败、修复与反证

首次团队导入遇到 Gitea 团队搜索响应中的 organization 为 null。修复为先确认组织范围，保存/导入再通过团队详情按 ID 核验实际组织，不能从同名推断身份。新增回归覆盖该实际响应格式。

首次真实 30 仓库执行 #18 全部记录“部分已修改”，未误报成功。原因是 POST 创建后的强推补全校验把已经移除 team_org 的 API 快照当作 Manager 输入，含审批/合并团队时校验失败。修复为按 API 回读格式构造中间状态；新增含多类团队的组合回归，并以真实批次 #23 复验创建路径。没有重放 #18；重新预览建立 #24，显示只需补全 release/** 的五个强推字段，30 库下发后独立回读通过。首次失败证据保留，不能记为首轮全通过。

审查同时补充了最终权限复查：写入期间名单权限变化时，即使规则数值恰好符合预期，也不能报告成功；有确定性回归反例。

## 操作数和耗时

人工基线为逐仓库在 Gitea 原生分支设置配置相同规则并保存。以下为浏览器自动化固定任务的实测，包含工具调度间隔，不能作为真人工时或生产性能。

| 固定任务 | 业务动作数 | 自动化经过时间 | 起止范围 |
|---|---:|---:|---|
| 原生 Gitea 新增一条规则：禁止推送、双人批准、指定 CI | 6 | 16.042 秒 | 已打开仓库分支设置 → 保存后规则列表；不含找仓库和导航 |
| Manager 空白创建相同限制的组织模板 | 8 | 12.521 秒 | 已选实例/组织 → 创建、填写模板名、添加规则、填写条件、保存后列表；不含批量下发 |

两个任务终点不同：原生步骤修改一个仓库，Manager 步骤保存可复用模板。这里只报告测量，不用两者相除得出效率改善。批次 #24 的新预览耗时 202.652 秒，提交至完成耗时 424.119 秒；包含共享限流、名单预检和完整回读。时间戳保存在批次 JSON。首次页面导入与排查混合计时单独保留，不作为熟练管理员效率基线。完整 30 库真人对照工时及 80% 指标仍未验证。

- Gitea REST API 无跨规则事务/条件写入；外部管理员恰在最终读取与写入之间操作的竞态不能由社区版 Manager 原子排除。已采取每步复查、停止后续写入和结果回读，不将此解释为原生强制治理。
- 未部署付费企业版验证继承能力；本阶段不依赖企业版接口。
- 真实千仓库吞吐、多节点 Manager、非本地文件系统及生产 Linux 升级业务验收未完成，均不在本地验收结论内。
- 网络中断与候选快速切换由确定性自动化测试覆盖，未对真实浏览器进行断网故障注入。
- 组织改名后旧模板需管理员重新整理归属显示；当前不提供组织改名的批量迁移工具。用户/团队改名已真实验证。

NON-BLOCKING FINDINGS：仓库相关 CI 历史通过原生链接访问；继续保留共享管理员审计，不能追溯自然人；后续组织强制治理需独立授权、豁免、漂移与版本设计。本次没有确认需阻塞交付的 P2/P3 问题。
