# AI Code Review 并发审查

## 配置与运行

Codex 审查支持同时处理 1 至 5 个 PR。新安装及缺少此配置的旧数据库默认使用 5 路，可在“AI Code Review → 模型与设置 → 同时审查 PR 数量”调整。

修改并发数即时影响任务领取。调低上限时，已经执行的任务继续，调度器等占用回落后再领取新任务。任务的模型、提示和资源预算仍使用创建时的冻结配置。同一个仓库的不同 PR 可以并发，同一个 PR 的新旧代次互斥。OpenCode 历史引擎继续串行执行。

系统仍部署一个 review-worker 和一个 review-executor。Worker 使用有界线程池，SQLite 短事务统一分配名额。每个 PR 的主审、反证、历史问题复核和发布顺序执行。管理页显示执行中、等待回收、排队和并发上限。

## 固定源码与中断恢复

每个任务使用独立 detached Git worktree，共享同一权限范围的仓库对象缓存。缓存更新和工作目录创建持有短期仓库锁，审查阶段并行读取各自固定的 Head。活动引用、工作目录和停止回执均按任务保存。

取消、版本过期和失败任务在确认执行器停止之前保留名额。一个任务待回收时，其余空位继续执行其他 PR。Worker 中断后，原执行锁释放且租约到期的任务优先领取自己的原名额，沿用原会话核对回执。发布恢复同样经过名额分配。未确认的执行状态不能作为清理工作目录的依据。

缓存清理会拒绝正在使用或待回收的仓库。缓存损坏且仍有其他任务占用时，当前任务明确失败并保留现场，其他任务退出后可以重新审查并重建缓存。历史任务继续支持原 Git 工作目录布局。

## 部署

执行器的 HTTP 线程数调整为 32，供长审查请求、事件查询、健康检查和取消使用。默认 Worker 内存上限为 2 GiB，执行器为 4 GiB、512 个 PID，临时空间为 768 MiB。Compose、首次安装与升级入口使用一致设置。模型计算继续通过 API 完成。

运行范围为单机可靠本地持久卷。实际宿主机容量应结合仓库规模、输出额度和真实 API 延迟验证。

## 验证记录

本次针对原子领取、跨进程抢占、动态调整、同 PR 代次互斥、独立工作目录、取消、租约恢复、旧数据与执行器容量增加了回归。隔离集成结果、真实 API 对照时间线、后台浏览器截图及资源记录保存在本次工作目录 `work/review-concurrency/`。

真实模型测试使用专用 Gitea 实例和合成 PR，不操作已有业务仓库。人工阅读及判断耗时尚无实测基线，人工精力节省 80% 未验证。内网宿主机部署与大仓库容量仍需在目标环境验收。
