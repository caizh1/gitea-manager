# 备份归档流超时修复

## 现场与根因

现场操作编号为 `20261015T190020Z-ce081afc`。首次异常位于 `append_artifacts()`：打开 Actions 制品归档流后，在消费流之前调用同一容器的 `readlink`。堆栈停在 Docker `exec_create` 等待响应，而不是 Git 导出或主备份 ZIP 下载。随后解锁与辅助容器删除请求也超时，留下实例锁。

独立 SSH 网关实测：32 MiB 归档不消费时，后续命令在相同的五秒测试阈值超时；先消费归档后命令约半秒完成。测试阈值仅缩短复现等待，生产的 120 秒超时保持不变，没有新增自动重试。小样本归档可能被缓冲而掩盖该问题，因此不能仅用空目录验收。

## 修复

- Actions 归档读取完成并关闭后，再执行路径校验；仍保留符号链接拒绝、正文摘要及有效制品完整性检查。
- Actions、主备份和 SSH 主机身份归档在异常路径关闭流，避免未完成传输继续阻塞容器操作。
- 备份首次错误不再被启动、解锁或辅助容器回收异常覆盖；清理异常保留在日志和异常备注中，客户端始终尝试关闭。
- 不自动删除未知实例锁；源服务启动失败时仍保留锁，避免未经确认开放新的数据操作。
