# 离线镜像身份兼容修复

## 原因与范围

2026-10-30 的 `manager-migration-trial-20261030-r1` 首次安装包为六个组件仅写入镜像配置摘要。原始镜像归档实际同时携带 OCI 镜像清单摘要，原安装器直接将 Docker 返回的 `Id` 与配置摘要比较，导致采用另一种镜像存储实现时拒绝同一镜像。

例如后端的配置摘要是 `sha256:595e85e7c24507976976b95674c79651c0bd172d26e8c552cb06973cb07ad765`，归档内关联的 OCI 清单摘要是 `sha256:88536e1d4ade0744981add4d5ed2ce9b913f9ac35910436be177ab1557647c99`。已读取该清单的原始字节验证摘要及长度，清单的配置字段明确指向上述配置摘要。其余五个组件也已逐项验证。

目标用户是首次安装管理员；支持输入是原版完整安装包与其已有的失败安装目录。人工基线为需要逐个检查镜像身份、修改安装脚本并避免破坏已有状态。补丁将正常修复收敛为应用补丁和重跑安装两个动作；未测量真实管理员耗时，不宣称达到减少人工精力 80% 的指标。

## 实现

- `deployment/image_identity.py` 从原归档核对配置、架构、OCI 摘要、字节长度及配置引用，只接受与交付清单已有身份相连的镜像。支持传统 Docker 归档及 OCI 索引；不按标签相同直接放行。
- `deployment/install.py` 同时认可经过上述核验的配置身份和 OCI 身份，继续要求 Linux amd64。失败时显示实际身份、架构和允许身份。
- `deployment/build-installers.py` 将全部已核验身份写入新清单，并携带身份解析模块，避免构建机与安装机的 Docker 存储实现不同导致误拒绝。
- `deployment/repair_image_identity.py` 是本次原包修复工具：核对原清单及原文件摘要后，仅替换两个安装器文件和包内校验表；获取安装与卸载的互斥锁，可在中断后重复应用。安装清单、状态、Compose、账号、密钥和业务数据均不修改。
- 业务代码修复在唯一 `master` 工作树完成；遗留迁移分支源码未修改。本次迁移安装包补丁仅基于已发布原件替换安装器校验函数，保留该包原有迁移服务配置。

## 验证

47 项相关单元与边界测试通过，覆盖配置身份、OCI 身份、嵌套索引、错误架构、错误配置关联、篡改摘要、跨命名空间标签、导入后再次核对、重复补丁、补丁损坏、原文件变化、安装互斥与状态保留。

发布原件副本的定向验收复现原报错；应用补丁后，同样的六个 OCI 身份响应全部通过。两次应用补丁后，安装清单与安装状态字节保持一致，继续初始化时复用原项目；补丁后的完整 `SHA256SUMS` 校验通过，原发布目录没有改动。Docker 响应在该定向验收中受控模拟，未执行真实容器。

原版镜像归档 SHA-256：`ae9ef00046a0814893f74c4d2174b22853daeebaac6a25ab9dc657fecfaf1352`。补丁约 23 KB，不包含镜像，不改变运行镜像层，无新增镜像或旧业务层叠加。
