# PR-Agent 审查执行器

## 配置与流程

在「AI Code Review → 设置 → 执行引擎」选择「PR-Agent 原生审查（Linux amd64）」。沿用 Manager 中的模型地址、模型 ID、API Key、思考控制协议、思考档位和预算。新安装默认使用 PR-Agent，模型 ID 预填 `deepseek-flash`。管理员配置实际模型地址和 API Key 后启用审查。升级沿用已保存配置，可在设置切换执行引擎，或点击「应用 PR-Agent 实测预算」后保存。应用预算时沿用现有模型地址、模型 ID 和 API Key。任务创建时冻结执行配置。

PR-Agent 使用原生 `PRReviewer` 审查固定 PR 标题、描述及变更文件上下文。新任务通过本地 Git 提供固定差异，旧任务沿用创建时的取码方式。Manager 维护 Git 增量缓存、固定版本工作树、证据定位、独立反证、历史问题编号、修复复审及自动发布。P0/P1 候选通过新的 PR-Agent 进程独立复核。历史问题由 PR-Agent 原生模型接口按复核约定判断。

PR-Agent 的模型输入以 PR 差异和变更文件上下文为主。跨文件自主搜索由 Codex 的原生工具提供。页面与结果将 PR-Agent 标记为差异审查，两个执行器的能力和质量结果应分别统计。

目标分支的 `.gitea/review-rules.md` 同时适用于 Codex 与 PR-Agent。所有阶段使用同一份固定规则。PR 中修改的规则在合并后生效。

## 完整性与发布

PR-Agent 的新增与删除合计上限为 30,000 行，包含整文件删除。Manager 先按 Git 原始补丁统计行数，再准备源码证据。发送模型前逐文件核对新增与删除行的位置及正文，包含 `.gitignore` 等普通文本文件。二进制、符号链接、子模块和无法核对的变更会显示在任务的覆盖详情。

默认以 UTF-8 读取每个固定版本的 Git 文件。旧仓库可在「仓库设置 → PR-Agent 源码备用编码」为整个仓库或指定目录设置 GBK、GB18030。目录填写仓库相对路径，整仓规则使用 `.`，最具体的目录优先。仓库配置接口使用 `source_encodings` 字段，例如 `{".":"gb18030","legacy/drivers":"gbk"}`。旧侧和新侧分别解码，固定提交中的原字节继续用于补丁与行内位置核验。无法无损解码时，详情会列出路径、版本侧及出错位置。

新任务使用协议 3。文件损坏、混编歧义或非普通文本导致覆盖缺口时，仍审查能够核对的文件。Gitea 总览标记“部分完成”，给出覆盖比例、优先列出编码问题，并链接 Manager 完整缺口清单。该结果没有整单 PASS。原始差异与固定 Git 提交的文件范围或已纳入审查的正文对不上时，任务停止。

历史问题的复核保留发给模型的证据表。原文来自固定提交。模型引用编号偏移时，只有同一问题、同一版本侧、同一变更块内的唯一正文匹配可纠正。无法确定时只补查该历史问题一次，仍不确定则保留待确认。历史 P0/P1 存在未决时保留审查门禁。

网关明确返回临时 TPM 限流时，任务显示“等待模型额度”。已结束的执行器释放占位，已完成阶段继续保留，到点恢复被拒绝的阶段。无重试时间时依次等待 1、2、5、10、15 分钟，此后以 15 分钟为基础错峰。重复点击重审会复用等待中的同版本任务。已提交但结果未知的调用仍进入原回执核对流程。

默认配置为 DeepSeek 协议、high 思考档位、1,000,000 token 上下文及显式 `max_tokens=393216`，请求、会话与任务时限各 3,600 秒，响应体上限为 64 MiB。Manager 在转发前检查完整请求与输出预留。支持的 DeepSeek 模型使用内置计数资源，未知模型在自动模式下采用保守估算。上游模型仍须支持所配窗口及输出额度。裁剪或遗漏变更、输出截断、位置无法核对及问题数触顶时，任务会显示失败原因。完成证据核验后自动发布。

任务级模型凭据通过 Manager 网关下发，PR-Agent 进程不持有实际模型 API Key。模型服务的 `low/high/max` 支持情况取决于实际服务；Manager 按所选协议传递参数。

## 离线构建

固定 PR-Agent 0.49.0，源提交为 `4ae117c4af71ec92e361f8dee1124439f8a7b4a3`。Python 3.12.15 Linux amd64 运行时与现有执行器一起交付，独立前缀位于 `/opt/pr-agent-runtime`。原执行器服务继续使用 Python 3.11。

联网准备机从固定源提交构建 `pr_agent-0.49.0-py3-none-any.whl`，按 `review-runtime/pr-agent-requirements.txt` 收集 Linux amd64 Python 3.12 的二进制 wheel，放入 `review-runtime/vendor/pr-agent-wheels/`。保存该提交的源码归档为 `review-runtime/vendor/pr-agent-source.tar.gz`，并准备 `cl100k_base`、`o200k_base` 的离线 tiktoken 缓存于 `review-runtime/vendor/pr-agent-assets/`。这些构建输入的 SHA-256 记录在 `review-runtime/依赖清单.json`。

构建前执行 `python3 scripts/review-runtime-prepare.py` 校验源码、wheel 与分词缓存。执行器多阶段构建通过 `--no-index` 安装固定依赖。运行镜像只复制已安装运行时和分词资源，wheel 与源码归档留在交付的构建材料中。

公网链路恢复并重新保存验收模型配置后，Manager 自动补审同一修复提交。随后新增提交通过 Gitea 事件触发审查，完整验证增量取码到发布。另一个全新仓库的重跑也遇到公网连接超时，失败记录保存在 `work/pr-agent-rules-acceptance/retry-attempt.json`。

执行器、仓库规则和自动发布的 78 项回归测试通过。真实验收证据在 `work/pr-agent-rules-acceptance/recovered-result.json`。本轮范围为 Linux amd64 模拟部署和公网 DeepSeek，内网模型及最终安装包留待统一验收。
