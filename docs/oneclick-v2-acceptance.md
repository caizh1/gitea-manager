## 故障注入与诊断盲判

独立排查者只读取 12 份诊断包，不访问目标系统、不补执行采集命令，均能识别失败阶段及直接错误事实。283 条 JSON/JSONL 可解析，归档与文件为 0600、目录为 0700；这些包未发现明文密码、私钥或 Token。详细证据见 `evidence/oneclick-v2-diagnostic-blind-review.md`。

实际触发的故障包括容器 64 MiB 限额 OOM、端口占用、SSH 私钥路径不存在、远端认证拒绝、主机指纹变化及备份目标容器缺失。SIGILL/Bun 文本、镜像挂载忙是明确标注的受控注入；磁盘不足使用 `/dev/full` 的 ENOSPC 注入，不等同于真实系统盘全部写满。

诊断能说明 OOM 与内存限额，不能据此认定内存泄漏；能说明指纹不匹配，不能认定攻击；能说明挂载忙，不能认定特定安全驱动。未知底层原因保留为未确定。

首次系统重启时三套实验 Manager 同时启动，执行器版本检查超过 30 秒；核心恢复，AI 正确显示不可用。此失败保留，不作为 PASS 覆盖。单套复验仍有会话检查超时，不能仅归因为多实例争用；已修复固定 2 秒短超时及重复 POST 会话的问题，修正后新镜像仍出现一次会话请求在剩余约 2.44 秒预算内超时；已记录未通过，而非追加无限重试或放宽预算。详见 `evidence/oneclick-v2-reboot-contention.md`。

额外恢复故障实测：向有效备份中注入无效 SQL，实际完成目标数据库删除与创建后触发导入失败；自动还原原数据库、重新生成原 Git SSH 授权并启动服务，核对仓库和加密密钥保持一致，锁已释放。此项直接验证回退执行路径。

新补运行诊断：Worker 保存实际启动检查、线程状态和 HTTP 结果，按稳定签名生成一次可下载诊断包；后台与 Worker 仅共享诊断卷，不把管理数据库或 SSH 私钥交给 Worker。缺失、过期及失败观测不混入旧安装成功检查。6 项运行状态与管理接口专项测试通过；部署后实际停止执行器，约 10.71 秒自动形成报告，管理员接口直接下载 1114 字节诊断包，确认未残留旧成功检查。
