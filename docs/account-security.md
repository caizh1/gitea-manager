# 账号与安全

登录后点击顶栏的“账号与安全”，可查看本人用户名、登录方式和角色。本地平台管理员可直接修改登录密码，无需操作数据库或修改部署环境变量。页面在尚未配置本机 IP 时也可使用。

## 修改密码

1. 输入当前密码。
2. 输入至少 12 位、与当前密码不同的新密码。
3. 再次输入新密码并点击“保存新密码”。

成功后当前浏览器保持登录，其他登录会话及复制的旧会话令牌全部失效。退出后使用新密码登录，重启或升级保留新密码。初始默认密码仍必须先修改才能进入业务页面。页面的显示密码按钮有独立名称，输入支持密码管理器；清空、离开页面和提交成功时会清除表单中的密码。

公司 LDAP / AD 账号显示目录改密说明；包括被授予平台管理员角色的目录账号，都应在公司目录修改密码。本页不修改目录密码、Gitea 用户密码、账号名称、权限或业务数据。忘记当前密码后的管理员恢复流程不属于本次功能。

## 安全边界

- 沿用当前本人账号接口 `/api/access/password`；不接收目标账号 ID，不提供替他人改密功能。
- 后端验证当前密码、密码长度及重复密码，写入密码哈希，同时更新旧版管理员密码存储。
- 会话令牌和 CSRF 随改密轮换；旧会话由服务器撤销。
- 两个并发改密请求只有一个能提交，另一个要求重新登录，不能覆盖已生效的新密码。
- 表单不将密码写入浏览器持久存储，审计与接口响应不包含密码或密码哈希。
- 网络异常时不假定操作失败或成功；界面提示确认新密码是否已生效。

## 设计与支持范围

视觉依据为用户确认的 [设计稿](assets/account-security-reference.png)。保留原有菜单层级和导航行为，侧栏主图标统一使用 Lucide 细线轮廓，图标以正常文档流排布。图标随构建产物离线交付，浏览器不需要访问外部图标服务。

目标用户是本地平台管理员，输入条件是已登录并掌握当前密码；公司目录账号仅展示改密路径。人工基线是原界面缺少登录后的改密入口，管理员需要请求运维介入或修改持久化配置。验收目标是本人在页面内完成身份核验、改密及会话更新，正常流程不需要运维介入。

固定验收覆盖默认密码首登、日常改密、无本机 IP、错误旧密码、长度和重复校验、CSRF、跨站拒绝、两浏览器会话、并发改密、目录身份及窄屏导航。功能与安全断言必须全部通过；本功能使用确定性校验，不涉及模型误报/漏报。尚未收集真实管理员与运维流程的对照耗时，不能据此宣称已经实测减少 80% 人工精力。

源码验证入口：`backend/tests/test_account_security.py`、`scripts/test_account_security_ui.cjs`。发布时需重新构建前端与后端镜像，使用 `scripts/review-package.py --export-images --source-image-tag <固定标签>` 生成完整离线包，不能只更新前端源码。
