# 主审与反证输出协议隔离

## 已确认的缺陷

用户任务 `481a56b094a3e8248ccc2a54e58d87db` 在主审阶段返回了只有 `checks` 的 JSON。旧主审系统提示同时展示了 `findings` 和 `checks` 两套格式，流程说明也同时要求主审和候选反证。模型可能选择错误的阶段格式；原程序正确拒绝了缺失主审报告的返回，但错误只显示为笼统的 `source_report_shape`。

## 修复

- 新任务使用第八版流程，快照与单元冻结 `phase-scoped-v1` 输出协议。
- 主审和关联审查只下发 `findings` 格式；反证只下发 `checks` 格式。用户消息也携带当前任务及预期顶层字段。
- 程序检查执行单元类型与候选输入是否一致，不让模型决定当前阶段。反证保留完整证据、保护条件和候选独立结论。
- 主审收到 `checks`、反证收到 `findings`，以及新协议混合两个顶层字段时均拒绝，明确记录 `source_phase_mismatch`、期望字段和实际字段。不把错误阶段报告转换为空报告。
- 旧任务的提示与计划保持冻结；升级后重新发起的任务才采用新协议。严格位置校验、全部变更覆盖、P0/P1 独立反证和一次位置纠错边界保持不变。
