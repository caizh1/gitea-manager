# PR diff 单次聊天审查

本次变更将新开始的审查改为：读取 PR 标题、描述和完整累计 diff，一次性提交模型，直接保存文字报告并发布为 PR Review。适用于能放入配置模型窗口的 UTF-8 Git diff，不限定 C/C++。不下载源码归档、不获取变更文件全文、不开放工程工具、不要求模型调用 StructuredOutput，也不追加模型总结轮次。

用户原先在 ChipMate 普通聊天中发送 PR 链接，反馈约五分钟完成；旧自动审查曾出现大量重复工具调用和上下文超限。这是用户报告的人工操作基线。本次对齐“提供 diff 后直接返回报告”的交互形式，不宣称复制 ChipMate 的全部系统提示词、参数或能力。思考和采样参数沿用已保存配置。

## 确定性边界

- 抓取 diff 前后核对 Head、Base、merge-base；发布前仍核对固定版本。发布回执丢失沿用原核对流程，不盲目重复发表评论。
- 新会话工作区为空；OpenCode 专用审查提示词替换通用编程提示词，全部工具权限拒绝。网关发出的请求无 tools、tool_choice 或 response_format；上游违规返回工具调用也不会执行。
- 正常文字停止即可完成。报告达到输出长度限制时保存现有文字并标记部分完成；空报告、上游异常、非法工具响应不能伪装成成功报告。
- 不从文字报告猜测问题数量、行号或 PASS；不自动创建行内评论。页面及 PR 状态评论标注仅 diff，保留报告全文，避免把空 findings 数组误称为零问题。
- 默认 262144 窗口、8192 输出预留，另预留 8192 的消息空间；使用 UTF-8 输入字节数保守约束单次容量，不冒称模型精确 Token 计算。超大 PR 明确要求拆分或配置更大的实际窗口，不静默截断或压缩原 diff。
- 二进制内容、未展示的函数、调用方、寄存器手册与构建配置不在输入中；此模式不能确认这些上下文中的缺陷或保护。并非完整工程审查，也不保证任意服务错误下都有有效审查结论。
- 升级前已经固定快照的工程审查继续原契约；历史结果保留。此前 usage 帧修复继续保留。

## 验收与审查

固定样本覆盖 Python 与 Markdown 混合 diff、仓库指令注入、PR 抓取期间更新、输入超限、报告持久化、发布回读及恢复去重、状态评论、Worker 无源码下载分支。真实交付 OpenCode 1.18.7 使用本地模型协议替身，覆盖正常文字、输出截断、违规工具和空响应；每场景恰好一次模型请求、零工具执行。旧工程模式的 200000、210000、260989 Token 三个压缩场景继续回归。

这些测试验证输入范围、运行与发布契约，不证明实际模型缺陷识别率、误报漏报率或原 PR 耗时。实际部署模型、原失败 PR、人工介入比例仍待内网部署验收；未宣称达到减少人工 80% 的目标。部署时优先使用同一 PR、同一模型、同一思考配置对比请求次数、耗时、报告准确性和人工补查量。

对当前改动检查版本漂移、恢复、工具越权、报告截断、HTML/发布标记注入、历史结果兼容及离线交付路径：VERDICT: PASS。P0/P1 BLOCKERS 为空。UNVERIFIED RISKS：实际模型质量与目标宿主机部署尚未验证。NON-BLOCKING FINDINGS：diff 外问题属于明确不支持范围；接口失败和输入容量不足仍需如实呈现。
