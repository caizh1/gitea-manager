# GitLab 与 Gitea 迁移实施记录

## 目标与当前边界

将其他 GitLab CE、GitLab EE 和开源 Gitea 的项目迁入指定 Gitea Enhancement 群组。当前开发分支为 `codex/gitlab-gitea-migration`。目标接收端基于用户确认的当前增强版独立源码快照；原增强版工作区未被修改。

目标用户为平台迁移管理员。输入为源端读取身份、目标管理员连接、目标群组、规则主体映射和来源停写确认。迁移不创建业务账号、不复制群组成员、不迁移 Runner，不自动冻结来源。历史批准作为历史资料保留，不计入当前有效批准。

人工基线包括逐仓导出代码和资料、下载上传文件、恢复关联、重建规则和逐项核验。验收目标是支持范围内必需字段和文件摘要差异为零、静默遗漏为零。人工节省百分之八十尚未进行对照计时，不能宣称达成。

用户确认暂时没有 GitLab EE 许可测试环境，优先完成本地可验证部分。早期代表性验收不等于全部版本、全部制品格式和全部企业能力已经支持。本轮完整固定基准和最终包证据见 `git-migration-advanced.md`。

## 已实现链路

1. 管理员登记来源；凭据使用独立持久密钥加密，支持密码及令牌。缺失原密钥时不得生成新密钥冒充恢复。
2. 独立串行 Worker 发现项目、固定元数据和可选 Git/LFS 快照。分页错误、读取权限不足、接口缺失均显式记录，不能当作空数据。
3. 管理员选择已有目标群组，确认停写并映射规则主体。计划固定源版本、盘点摘要、目标身份和群组授权摘要；同一请求标识不能换输入。
4. 在管理员名下建立私有隔离仓库，关闭 Actions 后传输代码。全部可见引用、默认分支、Git 对象和 LFS 内容进行核验；非分支引用经受控接收接口建立。
5. 导入原生议题、标签、里程碑、同仓及跨仓库 PR、评论、历史评审、行内评论和发布。保留来源身份、时间及稳定来源编号；重复提交核对原生内容与回执。
6. 迁移 Wiki Git 历史、议题和发布附件、通用及 npm／Maven／PyPI／NuGet／Helm 制品、完整可读取的历史 CI 文件；下载前后核对大小和摘要。通用制品在封存交接时发布为原生制品并关联最终仓库，再经原生下载协议核验。
7. 核对源端元数据和最终代码/Wiki 引用。只有没有读取缺口和待处理资料，才封存、在指定群组下建立受控层级、转移仓库、配置并回读规则。来源归档状态保留，Actions 不自动启用。
8. 每个写入步骤保存意图和稳定回执；重启或不确定结果保留现场，可从检查点继续。与目标备份、恢复、实例修改和其他迁移互斥；维护期停止领取和写入。

目标必须提供配套 `migration-capabilities` 协议。普通开源 Gitea 或尚未安装接收端的目标会在创建仓库前被拒绝。接收端不能以通用管理 API 调用成功代替。

## 数据和权限门禁

- 保密议题、保密或内部评论没有等价目标可见性时明确拒绝，不能降级为普通内容。
- 不按同名接管外部群组、仓库、规则或制品；只接受当前任务意图、标记及稳定编号对应的对象。
- 来源地址变化、重定向、对象摘要变化、目标授权变化、映射账号被同名替换均阻止交接。
- 规则主体映射为已存在的目标账号快照，不创建账号或成员授权。管理员必须确认静态名单；群组角色的后续动态变化不会自动同步。
- 历史批准已失效，不用于绕过目标当前审批。原始 CI 记录只展示和下载，不执行。
- 来源页面为空但 Wiki Git 不可读时，不能排除已删除页面的历史，保留为待处理项。
- 私有附件的下载只向校验后的来源地址发送凭据；外部链接不会携带源端凭据自动跳转。

## 尚未完成或未验证的范围

- GitLab EE 付费审批及完整企业规则；复杂群组继承和 Code Owners 的等价转换。已实现项目级 GitLab 重叠模式、Nobody 和强推，以及 Gitea 原生优先级与标签规则。
- 不可达历史提交、多行及图片讨论、完整关系和反应迁移、负责人及当前评审人映射。跨仓库依赖会自动加入固定批次，完整读取与停写确认必须覆盖全部依赖。
- OCI／容器镜像按用户最新要求暂不包含。除 npm、Maven、PyPI、NuGet、Helm 和通用包以外的制品协议未实现；其他版本的 CI 接口矩阵未验证。
- 旧版 Gitea 完整写入、所有 GitLab 版本矩阵；OpenSSD/QEMU 全量、生产规模、物理 Linux、真实生产和人工节省指标。
- 暂停/取消及不完整任务的管理收尾入口；失败现场的保留清理策略。

上述资料被盘点到且无法完整处理时，不得显示整仓迁移成功，目标保留隔离或归档。当前仍属于开发和隔离验收交付，不能据此批准全范围生产迁移。
