# GitLab 与 Gitea 迁移实施记录

## 已确认的交付目标

- 来源：GitLab 社区版、企业版，首期从 16.1.0 开始；开源 Gitea 按 2020 年起的版本适配。
- 目标：公司 Gitea Enhancement，在用户指定的群组下保留来源层级。
- 迁移代码、完整历史、LFS、Wiki、协作资料、附件、制品、历史流水线、日志和构建产物。
- 迁移分支保护和审批规则；不创建业务账号、不复制成员授权。规则人员由管理员集中配置，完成前不开放业务写入。
- 不迁 Runner 与流水线执行环境；保留原流水线文件。历史批准不自动算作目标平台的有效批准。
- 停写后按批迁移；不能静默遗漏、将读取错误当作空数据，或用归档替代本应可用的业务资料。
- 优先地址、账号、密码接入；遇到源端认证限制时提供令牌备用入口。

## 基线与验收口径

Manager 基线为 `a0ed5ab`，开发分支为 `codex/gitlab-gitea-migration`。增强版工作区存在其他未提交开发，不自动提交、回滚或混入本分支。

人工基线：逐实例登记项目、逐仓导出代码和协作资料、下载并重新上传制品、核对历史与附件、重建规则并逐条检查人员。

目标用户为平台迁移管理员。输入必须包括可读取所选范围的源端身份、目标管理员身份、目标群组和停写确认。完整性以源端固定清单为准；源端已删除、不可读或接口不能导出的对象必须明确区分并阻断无损交接。

固定样本使用 OpenSSD、完整历史的 QEMU，以及隔离平台中生成的讨论、附件、制品、流水线和规则。要求支持范围内清单覆盖率百分之百、文件及必需字段差异为零、静默遗漏为零，预置缺失与越权样本全部检出。人工时间包括人员配置，目标减少至少百分之八十；未实际对照计时前一律标记未验证。

## 实施顺序

1. 来源认证、分页发现、版本能力与完整性盘点；建立隔离验收样本。
2. 固定快照、持久任务、独立执行器、目标隔离与代码传输核验。
3. 协作资料、制品和历史流水线导入；补齐增强版已确认缺口。
4. 规则转换、人员配置、回读验证与交接。
5. 故障恢复、多版本和真实行为验收；构建并复验离线交付包。

## 必须先验证的缺口

- 现有 GitLab 导入器会将行内讨论转为普通评论；Gitea 导入器在缺少关联提交时可能跳过行内评论，不能直接作为无损实现。
- GitLab 新旧版本的密码授权、历史构建报告下载接口存在差异；连接成功不代表全部资料可读。
- 源端项目级制品与目标群组级制品的命名空间不同，必须检查同名不同内容和权限扩大。
- 分支规则的重叠、继承及审批主体语义不能仅复制字段后判为等价。
- 本机模拟数据不能证明企业付费能力、真实生产规模或人工节省指标。

## 当前状态

开发进行中，尚未完成迁移交付与无损验收。任何阶段性来源发现或盘点成功，都不代表迁移或业务交接完成。

### 已实现的只读链路

- 迁移中心增加 GitLab / Gitea 来源页面，复用平台管理员权限、会话和 CSRF 校验。
- 来源凭据使用独立持久密钥加密；原密钥缺失、损坏或被替换时拒绝继续写入凭据。
- 独立串行执行器负责认证、分页发现、元数据盘点和可选代码核验。记录不可变，来源版本变化后历史结果标记过期。
- 请求标识绑定来源、发现记录、项目范围、代码核验选项和发起人；相同标识不能用于不同输入。
- GitLab 16.1 的密码授权使用 `read_api read_repository`。真实版本拒绝在该授权中申请 `read_registry`；容器镜像内容授权尚未实现。
- 盘点保留议题、讨论、评审、规则、流水线、作业和制品接口元数据。403 与 404 记录明确缺口；认证失效、分页重复或容量超限导致失败，不伪装为空列表。
- 可选代码核验对比克隆前后的来源身份、引用和默认分支，运行 Git 对象检查，下载历史 LFS 并核对 SHA-256。现场留在 `git-migrations/code-snapshots/`。
- 网页只读取盘点摘要，完整元数据保存在数据库。二进制附件、作业日志、制品下载及 Wiki 核验尚未接入。
- Compose、首次安装和升级识别独立 `git-migration-worker` 与固定 Git Worker 镜像。维护期间暂停领取与恢复；重启将未完成任务标记中断，保留现场。

### 已取得的证据

1. 真实开源 Gitea 1.10.3 与 1.26.4：管理员密码认证、公开与私有仓库发现、议题和评论盘点通过。旧版使用管理员组织接口；无分页的旧接口依据实例接口描述读取，不把重复页当作完成。
2. 真实 GitLab CE 16.1.0：密码认证、群组与子群组仓库发现、接口元数据盘点通过。社区版审批规则接口返回 404，按缺口展示。
3. 真实私有 Gitea 仓库：两版 LFS 文件、功能分支和附注标签的读取与摘要核验通过。
4. 固定镜像 `git-migration-20261025-r4` 内的 Manager：登录、来源登记、异步发现、元数据盘点与两个历史 LFS 对象的代码核验通过。维护期间重启执行器后，迁移表内容摘要保持不变。浏览器已检查来源页面与盘点结果。
5. 上述容器运行于 macOS ARM 的 Linux amd64 仿真环境，不能替代物理 Linux、企业许可、多版本、大仓库或生产验收。
6. 本次来源、代码核验、认证、SVN 与升级相关回归共运行 125 项，123 项通过，2 项跳过；前端生产构建通过。
