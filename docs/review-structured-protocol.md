# 审查输出的源码位置协议

新建任务只要求 `findings` 数组。每条意见包含 `path`、`side`、`line`、`severity`、`title` 和 `body`；触发条件、因果链、影响与建议可自然写在正文中。`summary` 和 `limitations` 为可选字段。模型不负责生成内部证据编号或评论锚点。

`path` 是仓库相对路径；`side=new` 指固定 head 的源码，`side=old` 指固定比较基线的源码。`line` 是从一开始的源码行号，不能用 diff 文本行号代替。删除代码可以定位在旧侧。

Manager 只在当前单元实际提供的证据中查找位置；没有匹配、存在歧义或不能评论的主位置都明确报错，不选择最近行。行内锚点由固定快照生成，发布前仍核对 PR 版本。上下文行可放进 `related_locations` 提供多处证据，但不能冒充可评论变更。有效位置不表示问题成立，P0/P1 仍需独立反证。

反证每条候选要求 `id`、`decision`、`reason`，可附 `related_locations`。运行时检查候选完整覆盖；缺少显式位置时，反证仍看到该候选的完整相关代码及保护条件。没有检查完、无法判断与否定都不能发布为确认的阻塞问题。

仅对完整响应中的明确位置错误允许一次位置纠正；只允许修改位置及相关位置，不得删除意见、改变级别或改写正文。其他格式错误和未知回执不自动重放。新版本任务的明确输出截断可按既有关系或候选有限拆分，保留原失败并重新核对调用预算，不接受截断报告。旧任务继续使用其冻结的编号协议。

源码行号也可能被模型写错。本协议只减少字段和编号负担，不能代替真实模型的召回、误报及位置正确率验收。
