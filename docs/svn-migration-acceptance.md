# SVN 多来源迁移验收报告

## 交付范围

新增“SVN 迁移中心”，包含来源与仓库清单、跨来源计划、只读预检、作者映射、停写与完整读取确认、串行执行、进度事件、暂停取消、检查点恢复、私有群组、逐提交与远端回读验证、中文报告和显式工作区清理。

执行器是独立的 `svn-migration-worker`，不会在 Gunicorn 请求线程中执行迁移，不依赖相邻的 `gitea-enhancement` 源码，不挂载 Docker socket 或宿主机 SSH 密钥。数据库、工作目录与迁移密钥保存在同一持久卷。

最终运行镜像标签为 `svn-20261022-r9`，平台为 Linux amd64。目标验收使用真实增强版 Gitea `1.27.3+governance.20261020.r9`；不是模拟 Gitea API，也不把原工具的通过数量算作 Manager 集成通过数量。

## 使用者、输入与人工基线

使用者为 Manager 平台管理员，输入包括完整仓库 URL 清单、可读完整范围与历史的 SVN 账号、可信 CA、布局、可选作者映射及目标 Gitea 管理令牌。正式执行前由来源管理员备份并停写。连接成功不能证明不存在不可见目录。

人工基线是原命令行流程：逐仓准备布局和作者文件、运行转换、建立私有目标、推送、逐项核对、处理失败并汇总报告。Manager 自动化这些操作，但本次没有用户实际 SVN 的人工计时记录。**人工投入降低至少 80% 尚未验证，不能用按钮数量或机器运行时间替代人工计时。**

支持范围内的验收目标为零静默内容差异、零作者串用、零意外公开、零覆盖外部修改、零虚假成功。负面样本必须阻断；正面样本应完成完整核验。

该结论是当前实现的代码审查结论，不表示生产规模与人工节省指标已经验收。

本次审查覆盖源内容遗漏、历史引用、身份隔离、权限扩大、异步取消、进程组回收、重复请求、目标外部改动、密钥持久化、升级回退、SQLite 写事务、离线包身份和 HTTP 部署。发现的问题已修复并补充针对性回归：从 SVN 修订反向检查导入覆盖；扫描复制目录继承的历史 externals；使用兼容 HTTP 的随机幂等标识；升级回退包含迁移 Worker；在远端群组检查前提交盘点短事务；从仓库根按完整相对路径迁移嵌套项目，并提前收集复制来源的历史作者。

UNVERIFIED RISKS:

- 未使用公司的真实 SVN 或最大仓库，没有生产规模、生产证书与实际网络故障矩阵结论。
- 本次宿主为 macOS Docker Desktop，执行 Linux amd64 容器；原安装和升级入口通过不等于 Ubuntu systemd 真机验收。
- 尚未完成真实 HTTPS/公司 CA、多种认证服务、持续断网、实际磁盘耗尽与所有回执丢失位置的端到端组合测试。
- 来源读取完整性需要来源管理员提供可信依据；应用无法证明不可见目录不存在。
- 未采集人工基线与 Manager 实操计时，80% 人工节省指标待验收。

NON-BLOCKING FINDINGS:

- Git 不保留空目录，部分 SVN 属性仅进入报告，合并结果不等于完整 Git 多父合并图。
- 大仓库的全量逐提交验证成本尚未测量；不能把小型固定样本通过解释为大仓库容量结论。
- 账号创建、权限迁移、目录拆仓、CODEOWNERS 自动配置、externals 转换与增量同步均不属于本期。

## 离线包与运行边界

升级包使用正式 `review-package.py` 链路，携带固定 Worker 镜像与文件、镜像校验清单。首次安装包使用 `deployment/build-installers.py`，携带 Ubuntu 离线依赖和固定镜像。包中排除运行数据库、仓库内容、密钥、测试凭据、开发工作目录和 `node_modules`。

Docker Desktop 默认地址池已耗尽，隔离验收只为本次新项目预建了专用子网；没有修改用户部署或清理其他项目。曾在候选包切换期间触发镜像与清单不一致保护，旧服务未停止，原始拒绝记录保留。后续只使用固定包执行复验。暂停用例的首次脚本把“领取任务”误作“首仓已开始”，实际为首仓尚未开始即安全暂停；保留原断言记录后，将前置等待修正为单仓进入运行状态，原完成数与后续仓库未启动断言保持不变。旧版本多项目转换失败的日志和记录也保留，最终版本已对相同场景通过验证。

操作和恢复步骤见 [svn-migration.md](svn-migration.md)。
