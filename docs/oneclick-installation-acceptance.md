# 一键安装验收记录

## 范围与质量门槛

目标用户为在 Ubuntu 24.04 amd64 上首次安装产品的 IT 管理员。输入为完整安装包、root 权限、服务器访问地址及空闲端口；不要求人工编写 Compose、生成密钥、安装数据库或执行初始化 SQL。

人工基线为原流程中的依赖准备、离线镜像导入、Compose 配置、随机凭据生成与保存、数据库创建、管理员创建、Manager 本机地址设置、后台服务编排及逐项健康检查。目标为把这些安装与判断操作交给脚本，人工仅执行入口并填写地址、端口。暂未开展真实管理员的配对计时实验，不宣称已量化达到减少人工 80%。

阻塞门槛：任何失败被报告为成功、无效地址或端口被接受、重跑重置凭据或丢失业务数据、接管其他实例、离线安装依赖外网、暴露数据库或执行器管理权限，均不能通过。固定样本包含两套全新安装、真实 Git 访问、Manager 登录与后台心跳、重跑保留、端口占用、错误输入及包完整性校验。

## 当前验证

已在独立 Ubuntu 24.04.5 x86_64 虚拟机完成断网安装与真实接口验收。虚拟机采用 QEMU TCG、4 个虚拟 CPU、6 GiB 内存；网络为 `restrict=on`，无公网出口。安装包通过只读共享传入。

- 无 Docker 的系统：共用引导自动安装 Docker 29.1.3、Compose 2.40.3，APT 从本地 file 仓库安装，联网下载字节为 0。
- 最终两套安装包：使用全新业务数据卷，Gitea 仅输入地址、HTTP/SSH 端口，Manager 仅输入地址、HTTP 端口。没有人工生成凭据、修改 Compose 或执行初始化 SQL。
- Gitea 实际版本：`1.27.3+governance.demo.r5`。随机管理员登录、私有仓库创建、真实 SSH 克隆、提交推送及 API 回读提交均通过。
- Manager：随机密码登录、本机地址初始化、三个后台心跳、执行器真实版本健康检查，以及有效令牌返回输入校验错误 400、无效令牌返回 401 均通过；Sentinel 接口返回 404，AI 默认关闭且无模型 Key。
- 重跑：状态与密钥完全不变；修改后的 Gitea 密码仍有效，初始密码没有恢复；仓库 ID、提交及 Manager 登录和设置保留。
- 重启：没有运行安装或启动命令，Docker 与九个产品容器自动恢复。重启后的数据、凭据和登录回读通过，验证等待约 63 秒。
- 11 项单元与负向测试、Shell 语法检查、前端构建和差异空白检查通过。

本机模拟环境日志计时：Gitea 最终包首次安装约 82.9 秒，Manager 最终包约 81.5 秒，包含解压；已存在 Docker 和基础镜像缓存。重跑分别约 21.9 秒、35.4 秒。首次安装 Docker 的引导另行验证，不计入这两项用时；这些时间不是物理服务器性能承诺。

## 已发现的环境问题

首次 macOS Docker Desktop Manager 验收在创建网络时失败，原因为历史测试网络已经耗尽默认地址池，报错 `all predefined address pools have been fully subnetted`。未清理其他项目网络，没有重试相同失败。转用无历史容器和网络的独立 Ubuntu 24.04 amd64 虚拟机。

## 实测缺陷与修复

1. 执行器镜像需要可写的 `/app/review-native`，旧模板未挂载，健康接口返回 503。已增加独立持久卷，由一次性初始化容器设置 UID/GID 10001 和 0700 权限；运行服务继续保留只读根文件系统及最小能力。
2. 非 root 执行器不能读取宿主机 0600 的服务令牌。令牌改为 0444，宿主机父目录仍为 0700，外部用户不能穿越目录读取；有效与无效令牌均有真实接口验证。
3. 初始化容器修改卷归属后需要 FOWNER 才能调整权限。原始失败明确保存；仅初始化容器增加 CHOWN/FOWNER，实际执行器仍丢弃所有能力。
4. 多个容器同时把镜像目录复制到同一空数据卷，触发 Docker `file exists`。Manager 的共享数据卷采用 `nocopy`，应用自行初始化数据，最终全新卷并发启动通过。
5. 执行器查询真实 OpenCode 版本在模拟 CPU 上耗时约 6.9 秒，原健康检查的 5 秒超时过短。固定基线派生镜像仅将该超时改为 30 秒，安装器 HTTP 等待对应为 40 秒；最终仍要求真实版本和接口校验通过，不把错误降级为成功。
