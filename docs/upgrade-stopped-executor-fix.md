# 已停止执行器升级补丁

版本：manager-stopped-executor-fix-20261013-r2。

## 适用条件

用于已下载并执行 manager-review-upgrade-20261013-r1，已导入该版本固定镜像，但升级前置检查因已退出的 review-executor 返回 HTTP 409 的 Linux x86_64、Docker Compose v2、SQLite 持久化部署。补丁只更新升级控制器和入口，复用 r1 固定应用镜像；前置检查会校验每个镜像身份，不匹配时拒绝继续。

## 修复

升级器备份原密钥时使用 Docker 文件归档接口，支持运行中及已停止容器，并保留原文件内容和符号链接读取行为。不会在前置检查时启动原执行器，也不会跳过或重新生成原令牌。回退先恢复全部原服务配置，再只启动原先运行的服务，保证原停止服务的镜像、命令与停止状态得到恢复。

## 使用

将补丁解压到新目录，不覆盖原部署目录，也不要与 r1 包文件混放。在解压目录中执行：

```bash
sha256sum -c SHA256SUMS
sudo bash upgrade.sh --check
sudo bash upgrade.sh
```

如存在多个 Manager，给上述升级命令追加 --container 指定已有后端容器。升级会短暂停止 Manager，请避开正在进行的备份、恢复和审查；保留原部署目录里的私有升级记录。

## 验收

15 项升级控制器与数据门禁回归通过。真实隔离样本中，旧执行器先退出，原 exec 命令被 Docker 拒绝；同一补丁完成正常升级，并核对 Worker 与新执行器保留原令牌。迁移和健康检查后的故障注入成功回退，核对原数据库、旧密码、原停止执行器镜像、命令和停止状态。详细证据见 docs/evidence/upgrade-stopped-executor-20261013.json。

本机隔离验收不能替代用户目标机验收。r1 删除审查剩余额度倒计时的改动仍然保留；AI 审查预算超额导致失败的问题尚未修复。
